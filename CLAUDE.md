# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Reson8 is a self-hosted voice and text communication platform (TeamSpeak-3-style) with an Electron desktop client and a standalone Node.js server. Current version: 2.5.0, phases 1–16 complete — see "Project history" below before assuming something is unbuilt.

npm workspaces monorepo:
- `apps/client/` — Electron desktop client (TypeScript, no framework — vanilla DOM in the renderer)
- `apps/server/` — Fastify + Socket.io signaling server with mediasoup SFU (ESM, `"type": "module"`)
- `packages/shared-types/` — Socket.io event maps (`ClientToServerEvents`/`ServerToClientEvents`) and DTOs shared by both apps

## Commands

Databases (required before running the server):
```bash
docker compose -f docker-compose.dev.yml up -d   # Postgres + Redis only
```

Server (`apps/server`):
```bash
npm run dev            # tsx watch src/index.ts
npm run build           # tsc
npm run test            # vitest run
npm run test:watch      # vitest
npx vitest run src/__tests__/permissions.test.ts   # single test file
npm run db:migrate      # prisma migrate dev
npm run db:generate     # prisma generate
npx tsc --noEmit        # typecheck without emitting — the actual verification step used throughout this project's history
```

Client (`apps/client`):
```bash
npm run dev             # tsc --build && copy-html.mjs && electron .
npm run typecheck       # tsc --noEmit
npm run build:linux     # electron-builder (also :win, :mac)
```

Root:
```bash
npm run build            # tsc --build --force across all workspaces
npm run dev:server       # -> apps/server dev
npm run dev:client       # -> apps/client dev
npm run format            # prettier --write — works, prettier is installed
npm run lint              # BROKEN: references eslint, but eslint is not an installed dependency anywhere in the repo. Don't rely on it or tell users to run it.
```

There is no CI pipeline. `npx tsc --noEmit` (or `--build`) per affected workspace — shared-types, server, client — is the verification step consistently used before treating a change as done; run it in each workspace touched.

Shared-types must be built (`npx tsc --build`) before server/client typecheck against changes made there, since both consume it via the `@reson8/shared-types` workspace package.

## Architecture

**Voice (SFU, not P2P mesh):** `apps/server/src/services/mediasoup.service.ts` runs mediasoup Workers/Routers; each client uploads one audio track, the server forwards it to other channel participants. Signaling is a fixed 6-step handshake driven by `apps/server/src/handlers/voice.handler.ts` and `apps/client/src/services/voice.service.ts`: `GET_ROUTER_CAPABILITIES → CREATE_WEBRTC_TRANSPORT → CONNECT_TRANSPORT → PRODUCE → CONSUME → RESUME_CONSUMER`. Active-speaker detection uses mediasoup's server-side `AudioLevelObserver` (not client-side analysis, interval currently 100ms) and broadcasts `ACTIVE_SPEAKERS` — except for the *local* user's own halo, which is computed directly from the client's own analyser tap instead (no server round-trip needed for feedback about your own voice; see `renderer.ts`'s `startMicLevelMeter()`). Before the mic track is produced, it passes through a client-side Web Audio graph built once per join in `voice.service.ts`'s `buildMicProcessingGraph()`/`buildProcessingChain()`: `micSource → [noiseCancelNode] → gateGainNode → volumeGainNode → destination`, with the settings-panel level meter tapping the graph right after the (optional) noise-cancelling stage, and an optional self-hear monitor (`setSelfHearEnabled()`) tapping post-volume straight to local playback so a user can hear exactly how they'll sound — this same chain is also built in preview mode (`startPreview()`, used outside a voice channel), not just during a real call, so all three features behave identically either way. Noise cancelling itself runs DeepFilterNet3 via a vendored WASM build (`apps/client/assets/deepfilternet/`, not the npm package's default third-party CDN) inside an `AudioWorkletNode`, with adjustable suppression strength (`setSuppressionLevel()`, 0–100, default 60 — was hardcoded to the package's maximum before Phase 14, which caused a quiet/paused voice to fade toward silence).

**Chat pagination:** channel/DM history loads via cursor pagination (`FETCH_MESSAGES`/`FETCH_DIRECT_MESSAGES`'s `before`/`limit` params) — the client fetches only the latest 20 messages on open and loads more as an `IntersectionObserver`-driven sentinel pinned to the top of the message list scrolls into view (`renderer.ts`'s `loadOlderMessages()`), preserving scroll position on every prepend. A second sentinel at the bottom drives a floating "Jump to Most Recent Message" button, which rebuilds the tab from a fresh fetch if the true latest message isn't currently loaded (e.g. after jumping to an old pinned message).

**Link preview:** `main.ts`'s `fetchLinkPreview()` tries a plain `fetch()` + metascraper + OG-tag fallback first (fast, works for most sites), escalating to a genuinely hidden `BrowserWindow` navigation (`fetchLinkPreviewViaHiddenWindow()`) only when that returns nothing. Some sites block a bare HTTP client outright via IP-reputation/TLS-fingerprint bot management (e.g. Cloudflare) — no header or plugin change can get past this — but a real hidden Chromium window gets past it "for free" (confirmed live against a real bot-walled URL) since Electron already ships one, with no extra dependency needed. Capped at 2 concurrent fallback windows with a 15s timeout, since each is a genuinely expensive full renderer process.

**Presence-quit signaling:** a socket disconnect defers presence cleanup by a grace period (`connection.handler.ts`'s `pendingDisconnects`) so a brief network drop doesn't flicker someone's presence off and on — *except* when the client explicitly called `socket.disconnect()` itself (reported as Socket.io's `"client namespace disconnect"` reason, e.g. the app quitting via `main.ts`'s `"before-quit"`/window `"close"` handlers), which finalizes immediately since there's no ambiguity about a possible reconnect.

**Socket ownership (stale-socket race):** presence, mediasoup sessions and the grace timer are all keyed by `userId`, but a reconnecting user briefly has TWO live primary sockets — the new one and the old half-open one the server only reaps at its ping timeout (up to 45s). `apps/server/src/services/socket-ownership.ts` (`SocketOwnership`) records which socket owns each `userId`: `USER_JOIN_SERVER` claims it and `supersedeSocket()` (`connection.handler.ts`) retires the displaced socket immediately; the `disconnect` handler ignores any socket that isn't the owner, and the grace-timer callback re-checks `hasOwner()` before finalizing. Without this the old socket's late `disconnect` destroyed the live socket's voice session and presence (Phase 15 incident: users vanished from the online list and dropped from voice a second time ~12s after a blip — see progress.txt). Any new `userId`-keyed teardown in a disconnect path must go through this ownership check. Viewer sockets (`role: "viewer"`) are separate and never claim ownership.

**Chat messages (multi-line + Markdown):** the chat box is a `<textarea>` (Enter sends, Shift+Enter = newline) and message text is rendered as Discord-style Markdown. Rendering lives in `apps/client/src/markdown.ts` — a *pure* module (no Electron/DOM imports) on `markdown-it` — and is exposed through the preload as the synchronous `reson8Api.renderMarkdown()` (the renderer is a plain `<script>` with no bundler and a strict CSP, so it can't import markdown-it). Output is re-checked by an allow-list sanitizer (`sanitizeMessageHtml`) before `innerHTML`, and every message goes through the single `setMessageBody()` helper (channel, DM, edit, edit broadcast — never render message text any other way). Deliberately unsupported: raw HTML, images, tables, masked links `[text](url)` (spoofing), indented code blocks. A single plain line renders inline (the pre-Markdown `[time] nick text` layout); anything with a newline or block syntax is a block. Custom `:name:` emoji are an inline rule registered before `emphasis` (names may contain underscores) and read the emoji list the renderer pushes via `setCustomEmojis()`. Run `npm run test:markdown` in `apps/client` after touching `markdown.ts` — it includes XSS vectors.

**Emoji rendering:** emoji are plain Unicode text drawn with a vendored Google Noto Color Emoji web font (`apps/client/assets/fonts/noto-color-emoji/`, family `Reson8 Emoji`, first in the font stacks) so they look identical on every OS. Two traps: Chromium cannot render the OpenType-SVG build that npm redistributions (`@fontsource/noto-color-emoji`) ship — emoji come out blank — so the files are the COLRv1 woff2 subsets served by Google Fonts; and Google's `unicode-range` includes digits, `#`, `*`, `©`, `®`, `™`, which the vendored CSS strips (documented in its header) or every number would render as an emoji glyph. Form controls don't inherit `font-family`, hence the base `button, input, textarea, select` rule.

**Reaction hover card:** reactions carry `users: [{ userId, nickname }]` (`IReactionSummary` in shared-types, optional/additive). All reaction aggregation lives in `apps/server/src/services/reaction.service.ts` (one nickname query per batch of messages) — don't re-inline it in a handler. The client card is one shared `#reaction-card` element driven by delegated events with a 1s "pointer held still" dwell.

**Message layout, grouping & the hover toolbar:** every channel/DM message is built by the shared `buildMessageShell()` (`renderer.ts`) as `.chat-msg` > `.msg-header` (nick + HH:MM) + `.msg-body` (text + "(edited)"). Consecutive messages from the same author are *grouped* — a continuation (`.msg-continuation`) hides its header — when it lands within 5 minutes of the **group's first message** (not the previous one); a date divider, the "Unread Messages" separator or the sentinels break a group, and a reply (`data-is-reply`) always starts its own. `applyGrouping()`/`regroupFrom()` own this and MUST run wherever message elements are added or removed: after an append, after a prepend (it repairs the page junction), and after a delete (`removeMessageElement()`) — any new code path that inserts or removes `.chat-msg` elements has to do the same or headers go missing/duplicate. Actions (React, Reply, Edit, Pin, Delete — that order, via `insertToolbarButton()`) live in a floating `.msg-actions` toolbar, not in the reaction strip, which is `display: none` unless the message has reactions (`.has-reactions`).

**Replies:** `Message.replyToId`/`DirectMessage.replyToId` are plain columns with **no foreign key**, deliberately — `ON DELETE SET NULL` would erase the fact that a message *was* a reply, and the client says "Original message was deleted". The server resolves snippets in one batched primary-key query per page (`reply.service.ts`, mirroring `loadReactorNicknames`) and ships them as `replyTo: IReplyPreview` (one level only — a snippet never nests). A reply into another channel/conversation is refused (it would leak that text into the snippet); a missing target is accepted and renders as deleted. Client side, reply drafts live in `replyTargets` keyed by tab id, the bar is the first child of `#chat-composer`, Escape cancels it only when the emoji autocomplete didn't consume the key, and `jumpToMessage(tabId, messageId)` (channels via `FETCH_MESSAGES`, DMs via `FETCH_DIRECT_MESSAGES`' `aroundMessageId`) serves both reply snippets and the pinned bar.

**Uploads — the stored-file ledger (security-critical):** the server never trusts a file URL or Cloudinary `public_id` from a client. Every stored file is a `StoredFile` row (`kind`, `ownerId`, `claimedAt`); an HTTP upload is attributed to a user by a socket-issued bearer token (`REQUEST_UPLOAD_TOKEN`, hashed in Redis, 10 min) and returns an `uploadId`; a message/DM/emoji/icon *claims* it by id with `claimUploads()` — one atomic `UPDATE … WHERE claimedAt IS NULL AND kind = ? AND (ownerId = me OR ownerId IS NULL) RETURNING`, run on the **same transaction** as the write that uses it. Deleting always goes through `releaseStoredFile()` AFTER the referencing row is removed, using the ledger's own url/public_id and only when nothing else still references the file; a URL the ledger doesn't know is never deleted. Never persist or delete a client-supplied URL/public_id anywhere. Local-disk files are stored by their host-independent path (`/uploads/<file>`) and the client resolves them against the server address (`resolveMediaUrl()` in `preload.ts`, applied at every inbound entry point). Unused uploads are cleaned up three ways: `DISCARD_UPLOAD` (immediate), an hourly sweeper for uploads unclaimed after 24 h (`upload-sweeper.ts`), and `npm run uploads:prune` for pre-ledger leftovers. Message images live in the `attachments` table (up to 10 per message); `Message`/`DirectMessage.attachmentUrl` are deprecated and no longer written (expand/contract).

**Composer:** `#chat-composer` stacks [reply bar → attachment tray → input bar]; `switchTab()` toggles it. Picked images are `pendingAttachments` (global, not per tab): uploaded at once, at most 3 concurrently, each shown as a persistent preview card with preview/remove/retry, and Send is blocked while any is uploading or failed. Typing `:` + a letter opens the emoji autocomplete (all in `renderer.ts`; its element refs live at the top of the file because `switchTab()` calls into it during startup).

**Identity:** no login/auth system. Each Electron install generates a persistent UUID (`apps/client/src/instance-id.ts`, stored under `app.getPath('userData')`) sent as `instanceId` on `USER_JOIN_SERVER`; the server upserts a `User` row and assigns default role via this ID. `ADMIN_INSTANCE_ID` env var grants Server Admin automatically. Dev mode regenerates the UUID each launch for easy multi-client testing — packaged builds (`app.isPackaged`) persist it.

**Permissions:** bitwise flags on `bigint` role columns, defined in `packages/shared-types/src/models.ts` (`PermissionFlags`: `CONNECT`, `SPEAK`, `MANAGE_CHANNELS`, `MANAGE_ROLES`, `KICK_USER`, `BAN_USER`, `ADMIN`, `MANAGE_EMOJIS`). `apps/server/src/services/permissions.service.ts` aggregates a user's roles via bitwise OR; `ADMIN` bypasses all checks. Socket.io handlers are gated with `requirePermission()` from `apps/server/src/middleware/permissions.middleware.ts`; `requireAnyPermission()` in the same file gates a handler shared by more than one permission (e.g. `GET_ALL_USERS`, needed by both `MANAGE_ROLES` and `BAN_USER` holders for the User Management tab).

**Presence:** tracked in Redis (`apps/server/src/services/presence.service.ts`), not Postgres — who's connected to which server/channel, with a TTL refreshed on activity. On `USER_JOIN_SERVER`, `hydrateOccupants()` in `connection.handler.ts` walks the channel tree and populates occupants from Redis before emitting `CHANNEL_TREE_UPDATE`. `resolveNickname()` falls back to Postgres when a Redis presence read races a reconnect (see progress.txt PRD 3.2).

**Protocol contract:** `packages/shared-types/src/socket-events.ts` (`ClientToServerEvents`/`ServerToClientEvents`) is the source of truth for the client↔server wire format. When a feature crosses that boundary, update shared-types first — both apps typecheck against it.

**Data model:** Prisma/Postgres (`apps/server/prisma/schema.prisma`) holds `Server`, `Channel` (self-referencing tree via `parentId`, re-parentable after creation via `CHANNEL_MOVED`, cycle-checked server-side; `iconEmoji`/`iconUrl` give text channels a custom tree icon, mutually exclusive, no distinct "category" `ChannelType` — a channel is a category simply by having children), `User`, `Role`, `Message`, `DirectMessage`, `BannedUser`, `Reaction`, `ChannelRead` (per-user-per-channel unread cursor), `CustomEmoji` (server-uploaded emoji, PENDING/APPROVED), `StoredFile` (the upload ledger — see "Uploads" above) and `Attachment` (a message/DM's images, in order). `Message`/`DirectMessage` also carry `replyToId` (a plain column — see "Replies"). Channel tree is flattened→nested in `apps/server/src/services/channel-tree.service.ts`.

**Client process boundaries:** `main.ts` (Electron main — window, tray, global shortcuts for PTT, permission handler for mic access, link-preview fetching via `metascraper`, native context menu) → `preload.ts` (contextBridge API surface, `reson8Api`, 60+ methods) → `renderer/renderer.ts` (vanilla TS DOM UI, no framework/build tooling beyond tsc).

**Electron gotchas that have bitten this project before** (see progress.txt for the incidents):
- `getUserMedia` is silently blocked by default — `session.defaultSession.setPermissionRequestHandler` in `main.ts` must auto-grant mic/audio permissions.
- Detached `new Audio()` elements produce no sound in the renderer; audio elements must be `document.createElement("audio")`, appended to `document.body`, and removed after use.
- Files referenced by the main process (tray icon, sound alerts under `apps/client/assets/`) must be listed in electron-builder's `build.files` in `apps/client/package.json` or they silently vanish from packaged builds while working fine in dev.
- electron-updater's GitHub provider needs `latest.yml`/`latest-linux.yml`/`latest-mac.yml` (electron-builder generates them locally under `apps/client/release/` alongside the installers) uploaded as release assets on every GitHub release — `npm run build:*` alone does not publish anything, so a release built and uploaded by hand without those yml files leaves every platform's update check silently failing (v1.3.0 → v1.4.0 incident, see progress.txt).
- A `main.ts`/`preload.ts`/`voice.service.ts` static `import` of an ESM-only npm dependency (a package with no real `"require"` export condition, or one whose own `package.json` sets `"type": "module"` — which makes Node treat *all* its plain `.js` files as ESM regardless of which export condition points at one) compiles to a `require()` call under this project's CommonJS `tsconfig` and crashes the whole preload script at startup with `ReferenceError: exports is not defined` (the `deepfilternet3-noise-filter` incident, Phase 13, see progress.txt) — check a candidate dependency's `package.json` `"type"`/`"exports"` *before* adding it. A plain `await import(...)` isn't a safe fix either: TypeScript rewrites dynamic `import()` back into a deferred `require()` under this same CommonJS target, hitting the identical crash lazily instead of at startup. The confirmed-working escape hatch when an ESM-only dependency is unavoidable is an indirect-eval dynamic import — `new Function("specifier", "return import(specifier)")` — which TypeScript can't see or rewrite (see `voice.service.ts`'s `dynamicImport` helper). That helper only works with an actual URL, though — calling it with a *bare* package name (`dynamicImport("some-package")`) throws `Failed to resolve module specifier` in a real (non-sandboxed) Electron preload, both unpacked and packed into a real `.asar`: unlike Node's own `import()`, this path has no concept of bare specifiers/node_modules resolution and needs a real URL. Resolve the bare name to an absolute `file://` URL first — `require.resolve()` (safe even for an ESM-only package: it only computes a path via the "require" export condition, it doesn't execute the file) then derive the actual ESM sibling file and `pathToFileURL(...).href` it — see `voice.service.ts`'s `resolveNoiseCancelModuleUrl()` (the v2.2.1 noise-cancelling incident, Phase 13, see progress.txt — this bare-specifier form never worked in any environment, dev or packaged, despite passing typecheck and the preload-crash fix).
- `apps/client/src/renderer/index.html`'s CSP `script-src` must include `blob:` — an `AudioWorkletNode`/`AudioWorklet.addModule()` built from an in-memory `Blob` + `URL.createObjectURL()` (the noise-cancelling engine builds its processor this way) is governed by the `script-src`/`script-src-elem` CSP directive, not `worker-src` as the name might suggest, and without it fails with the unhelpful `AbortError: Unable to load a worklet's module.` (no explicit CSP violation surfaces in the toast — only in the console) (v2.2.1 incident, see progress.txt).
- On Windows, an app-icon re-launch that "froze" the window was addressed (hypothesis-driven, user-confirmed OK) by two things in `main.ts`: minimize-to-tray intercepts `will-minimize` and `hide()`s instead of hiding from inside the post-hoc `minimize` event (which left the window both minimized and hidden), and Chromium's `CalculateNativeWinOcclusion` feature is disabled on `win32` (it can wrongly mark a restored window occluded and stop painting it). All "bring the window forward" paths (second-instance, tray click, tray Restore) go through `showMainWindow()`, which logs window state. Window size/position/maximized persist via `apps/client/src/window-state.ts` (hand-rolled, validated against current displays; Wayland ignores app-set positions).
- Image-viewer actions that need Node/Electron (`openExternal`, clipboard, fetching image bytes without CORS) go through validated main-process IPC (http(s) only, `image/*`, 25 MB cap, 15s timeout) — never direct renderer access.
- Installers currently ship **unsigned** (no code-signing certificate) — on Windows, `main.ts` replaces `NsisUpdater`'s `verifyUpdateCodeSignature` with a verifier that always resolves `null` (not a boolean; it's a `(publisherNames, path) => Promise<string | null>` function per electron-updater's API). Without this, electron-updater checks a downloaded update's Authenticode publisher against the publisher name baked into the *currently-installed* app's own `app-update.yml` and rejects a legitimate unsigned update with "not signed by the application owner" (v2.2.0 incident — hit when updating a client that had been built and installed while still signed, see progress.txt). If code signing is ever reintroduced, that override must be removed again so updates are actually verified — see the "Code Signing" section in the root README.

- The main window must never navigate away from the app's own page: a file dropped on Chromium's default drop target navigates the window to that file and replaces the whole UI. `main.ts` cancels it with a `will-navigate` handler (defense in depth) and the renderer swallows every drag that carries `Files` (`dragover`/`drop` guard) — text drags, including the channel tree's own reorder drag, are left alone.
- Any payload that carries a file URL (message `attachments`, emoji `imageUrl`, channel `iconUrl`) must be run through `resolveMediaUrl()` in `preload.ts` before reaching the renderer — new local-disk files arrive as server-relative paths (`/uploads/x.png`) and render as broken images/icons otherwise. A v2.4.0 client does not do this, which is why it cannot show *new* locally-stored files from a v2.5.0 server.

## Environment

Server needs `apps/server/.env` (copy from `.env.example`): `DATABASE_URL`, `REDIS_URL`, `PORT` (9800), `MEDIASOUP_ANNOUNCED_IP`; optional `ADMIN_INSTANCE_ID`, `SERVER_PRIVATE_PASSWORD`, `MEDIASOUP_PRIVATE_ANNOUNCED_IP` (LAN/WAN dual-announce for hairpin NAT), `CLOUDINARY_*` (image uploads fall back to local disk storage if unset).

Ports: 9800 (Fastify + Socket.io signaling), 10000–10100 UDP/TCP (mediasoup media), 5432 (Postgres), 6379 (Redis).
