# AGENTS.md — apps/client

Guidance specific to the Reson8 Electron client. See the repo-root `AGENTS.md` first for architecture and cross-cutting conventions (shared-types-first workflow, progress.txt logging requirement, etc).

## Commands

```bash
npm run dev             # tsc --build && copy-html.mjs && electron .
npm run typecheck        # tsc --noEmit (verification step)
npm run test:markdown     # Markdown renderer incl. XSS vectors (after touching markdown.ts)
npm run test:avatar       # avatar.ts (hashes, URL builders)
npm run test:soft-clip    # services/mic-soft-clip.ts (mic clipper math)
npm run test:link-fixers  # link-fixers.ts (host mapping, entity decoding)
npm run test:media-proxy  # media-proxy.ts + the open-ended range probe / guarded raw fetch (local servers that behave like the Invidious host)
npm run test:link-preview # link-preview-guard.ts / link-preview-fetch.ts — blocked-address table, head reader, caches, redirects, deadlines (starts local HTTP servers)
npm run test:identity     # identity-proof.ts — signs with the client, verifies with the SERVER's built verifier (build apps/server first)
npm run test:identity-backup  # identity-backup.ts + identity-store.ts — backup format/tamper cases, and the store's migration/locked/replace logic with a fake OS cipher
npm run test:tls          # tls-trust.ts / tls-store.ts / tls-probe.ts — address parsing, the scheme decision table, the pin store, and the probe against real local servers (HTTPS cases need openssl)
npm run test:saved-passwords  # saved-passwords-store.ts — the password file's rules with a fake OS cipher (PRD 19 C1)
npm run test:version      # app-version.ts — semver ordering incl. -beta.N, prerelease channel (PRD 19 R0)
npm run test:window-chrome   # window-chrome.ts — frame options and the title-bar choice (PRD 19 R7)
npm run test:server-health   # server-health.ts — the saved-server latency probe URL (PRD 20 W1)
npm run test:update-prefs    # update-prefs.ts — the "Get beta updates" preference file (PRD 20 G1)
npm run build:linux       # electron-builder --linux via scripts/electron-build.mjs (also :win, :mac) — adds -c.publish.channel=beta for a prerelease version (scripts/update-channel.mjs)
```

`npm run dev` is the full loop — it rebuilds TS, copies `renderer/index.html` into `dist/`, and launches Electron. There's no watch mode; re-run after changes.

## Structure

- `src/identity-key.ts` + `src/identity-proof.ts` (PRD 17.12) — this install's Ed25519 identity key. `identity-key.ts` is MAIN-PROCESS ONLY (`<userData>/identity-key.pem`, 0600; ephemeral in dev) and exposed solely through the `identity-get-public`/`identity-sign-challenge` IPC; `identity-proof.ts` is the pure half (message format, fingerprint, a signer that refuses anything but a server-shaped nonce + plain host). See the root `AGENTS.md`'s "Identity".
- `src/identity-store.ts` + `src/identity-backup.ts` (PRD 18.6) — the key's storage rules and the backup file. `identity-store.ts` is Electron-free (the OS cipher is injected) and owns migration, the `locked` state and replace-on-import; `identity-backup.ts` is pure (scrypt N=2^17 + AES-256-GCM with the header as AAD; a file's cost parameters are never trusted). `identity-key.ts` is now just the Electron adapter (`safeStorage` + `userData`). Main-process IPC: `identity-get-status`, `identity-export`, `identity-import-pick`/`-decrypt`/`-apply`, `identity-create-new`; file dialogs and key material never reach the renderer.
- `src/tls-trust.ts` + `src/tls-probe.ts` + `src/tls-store.ts` (PRD 18.3) — encrypted connections. `tls-trust.ts` is PURE (address parsing, `decideScheme()`, `identityHostOf()`, fingerprint formatting) and reaches the renderer through `reson8Api.tls.*`; `tls-probe.ts` (Node `tls`, no Electron import) classifies a server as trusted / untrusted / no-tls / unreachable and returns the presented certificate; `tls-store.ts` is the pin + HTTPS-memory file in `userData`, used only by `main.ts`. See the root `AGENTS.md`'s "Encrypted connections" for the rules and the two-TLS-stacks trap.
- `src/avatar.ts` (PRD 17.1) — pure: email normalization/SHA-256, Libravatar/Gravatar URL builders (mirroring the server's, used only for the Settings preview), the `sha256(userId)` default avatar, `withAvatarSize()`. Exposed as `reson8Api.avatar.*`.
- `src/link-preview-fetch.ts` + `src/link-preview-guard.ts` (PRD 18.10) — the fast link-preview path and its safety rules, both Electron-free and covered by `npm run test:link-preview` (local servers; the production guard is also asserted to leave a local listener untouched). `main.ts` keeps the IPC, the caches and the hidden-window fallback. The `undici` dependency is pinned to `^7` because the main process runs Electron 34's Node 20.19 (undici 8 needs Node ≥ 22.19); import BOTH `fetch` and `Agent` from the package (mixing it with Node's global `fetch` is unsupported). Don't weaken `isBlockedAddress`/`checkPreviewUrl` to make a test pass — the tests use the `allowPrivate` option instead.
- `src/link-fixers.ts` (PRD 17.9) — pure: the social-media fixer host table, the crawler UA, `decodeHtmlEntities()`. Used by `main.ts`'s link previews.
- `src/main.ts` — Electron main process: window creation, system tray, global-shortcut PTT registration, mic permission auto-grant, native right-click context menu, link-preview fetching via IPC (a fast `fetch()`+metascraper+OG-tag path first, falling back to a genuinely hidden `BrowserWindow` navigation — `fetchLinkPreviewViaHiddenWindow()` — only when that path is blocked or finds nothing, e.g. sites behind Cloudflare-style bot management), `is-window-focused` IPC handler. It also cancels any main-window navigation away from the app's own page (`will-navigate`, PRD 16.10 — a dropped file must never replace the UI).
- `src/preload.ts` — the entire `contextBridge` surface (`reson8Api`, 60+ methods) exposed to the renderer. Any new capability the renderer needs from Node/Electron/Socket.io goes through here. It also owns the upload plumbing: `getUploadToken()` (socket-issued bearer token, cached, 5 s timeout so a pre-v2.5.0 server just falls back to a tokenless upload), `uploadTo()` (retries once on a 401) and `resolveMediaUrl()`, which every inbound payload carrying a file URL (messages, DMs, emoji, the channel tree) goes through — see the root `AGENTS.md`'s "Uploads" paragraph.
- `src/renderer/renderer.ts` — the UI itself: vanilla TypeScript + DOM, no framework. Channel tree rendering, tabbed chat (cursor-paginated, `IntersectionObserver`-driven infinite scroll-up), settings modal, emoji picker, sound alerts, all client-side state. Message building (`buildMessageShell`, grouping, the hover toolbar, replies), the composer (reply bar, attachment tray, input bar), the emoji autocomplete and the NSFW/mute preferences all live here, in sections marked with their PRD numbers.
- `src/renderer/index.html` — markup + all CSS (no separate stylesheet or CSS framework).
- `src/services/voice.service.ts` — mediasoup-client engine: transport/producer/consumer lifecycle, the 6-step handshake client side, device selection. Owns the send-side mic processing graph (`micSourceNode → [noiseCancelNode] → gateGainNode → volumeGainNode → softClipNode → destination → produce()`; the soft clipper from `services/mic-soft-clip.ts` is a pass-through at ≤100% mic volume and, above it, takes `volume/3` and applies ×3 in its curve — a WaveShaper clamps its INPUT to [-1, 1], so the gain has to be folded into the curve; ceiling 0.99 for the 2x oversampler's overshoot; self-hear taps the clipper) — noise gate (GainNode envelope, not `track.enabled`), mic volume, AI noise cancelling (DeepFilterNet3 via WASM, loaded through an indirect dynamic `import()` — see Conventions below, adjustable suppression strength via `setSuppressionLevel()`), and an optional self-hear monitor (taps post-volume straight to local playback) all extend this one graph rather than each building their own.
- `src/markdown.ts` — chat Markdown renderer: a *pure* module (no Electron/DOM imports) on `markdown-it`, imported by `preload.ts` and exposed to the renderer as `renderMarkdown`/`markdownToPlainText`/`setCustomEmojis`. See the root `AGENTS.md`'s "Chat messages" paragraph; verify changes with `npm run test:markdown` (`scripts/markdown-smoke.mjs`, includes XSS vectors).
- `src/window-state.ts` — persists/restores the main window's bounds + maximized state (`userData/window-state.json`), validated against the displays that currently exist; every failure falls back to defaults.
- `src/instance-id.ts` — persistent UUID generation/storage (fresh per launch in dev, persisted in packaged builds).
- `assets/` — tray icon, sound-alert `.mp3` files, app icons, and `deepfilternet/` (the vendored noise-cancelling WASM + ONNX model, ~24MB, fetched via a relative path from `index.html` exactly like the sound alerts — deliberately vendored rather than left on the package's default third-party CDN). `fonts/noto-color-emoji/` holds the vendored COLRv1 emoji font (see the root `AGENTS.md`'s "Emoji rendering" — don't swap in the SVG-format build, and keep the stripped `unicode-range`s). Anything added here must also be added to `build.files` in `package.json` or it won't exist in packaged builds (bit this project once — see root AGENTS.md's Electron gotchas).

## Conventions worth knowing

- Message text is only ever rendered through `setMessageBody()` in `renderer.ts` (Markdown → allow-list sanitizer → `innerHTML`); the chat input is a `<textarea>` auto-sized by `autosizeChatInput()` (it adds the border back — `scrollHeight` excludes it — or a scrollbar sliver appears).
- The image viewer (`openLightbox(url, meta?)`) lays the image out at natural size and zooms/pans with `transform` only; its toolbar actions use the validated IPC in `main.ts` (`open-external-url`, `copy-text-to-clipboard`, `copy-png-to-clipboard`, `fetch-image-bytes`). The reaction hover card is one shared `#reaction-card` (`showReactionCard`/`hideReactionCard`), re-hidden whenever a reaction bar is rebuilt.
- Connecting (PRD 18.3): `startConnect()` → `resolveConnectionTarget()` in `renderer.ts` probes first (IPC `tls-probe`, one round trip returning the result + any pin + the HTTPS memory), applies `decideScheme()` and only then calls `api.connect({ scheme, host, port, pinned }, …)`. `preload.ts` owns `serverBaseUrl` (read it with `api.getServerBaseUrl()`; the renderer no longer keeps its own copy). Dynamic text in the trust/changed modals goes through `textContent`; the `localStorage` key `reson8-tls-http-warning-dismissed` (a `host:port` array, capped at 100) remembers dismissed "not encrypted" warnings per server.
- Modals opened FROM the Settings modal (the identity export/import/locked ones) need a higher `z-index` than it and the override must come AFTER the base modal block in `index.html`, or they open invisibly behind Settings — check with `document.elementFromPoint()`, not just the `visible` class. `RESON8_FORCE_PERSISTENT_IDENTITY=1` is a TEST-ONLY switch that makes an unpackaged build persist its key and instance id like a packaged one (always with a throwaway `--user-data-dir`). To drive native file dialogs headlessly, stub `dialog.showSaveDialog`/`showOpenDialog` through the main-process inspector (`--inspect=<q>`, `Runtime.evaluate` with `includeCommandLineAPI: true` to get `require`) and use a persistent `Xvfb` (not `xvfb-run`, which would tear the display down when the app relaunches itself).
- The own-voice speaking halo is gated on `isLocalMicTransmitting()` (not muted, not deafened, PTT held in PTT mode) — the local analyser taps before mute takes effect, so level alone is not "being heard".
- To test renderer behavior against the real built app without a UI harness: launch `electron . --remote-debugging-port=<p>` (add `--inspect=<q>` for the main process) and drive it over the DevTools protocol; trusted mouse events via `Input.dispatchMouseEvent`. (Don't `pkill -f` a pattern that also appears in your own command line.)
- The main/preload/renderer boundary is a real security boundary in Electron — new features that need Node or IPC access get a `preload.ts` method, not direct access from the renderer.
- Audio elements: always `document.createElement("audio")` appended to `document.body`, never a detached `new Audio()` — see root AGENTS.md.
- Access (PRD 18.18): `hasServerAccess` mirrors the server's answer (join ack + `access-changed`); every entry point that would open a channel/DM tab, join voice, attach/paste/drop files or nudge goes through `requireServerAccess()` (a toast with the banner text). `applyAccessState()` closes tabs with `reason: "access"` (kept tabs stay remembered) and, when access returns on a live connection, restores kept tabs and unread DM tabs without a reconnect. `restoreKeptTabs()` does nothing while restricted and leaves `keptTabsRestored` unset so the tabs return later. `body.no-access` only greys things out — the guards and the server are the real check.
- DM unread (PRD 18.13): `unreadDmPartners` is the DM counterpart of `unreadChannelIds`, and a DM counts as read ONLY through `markDmTabRead(tab)` — tab active AND `document.hasFocus()` (sync; never `api.isWindowFocused()`) AND its page has been rendered (a tab that is active merely because it was just created hasn't shown anything). Call it from the places that make something visible (switchTab, window focus, after the history page renders, the `dm-received` handler); never call `api.markDmsRead()` directly. DM messages collapse like channel messages (`attachMessageTruncation()` in `renderDmMessage()` and the prepend path).
- Scrolling (PRD 18.12): never write `messagesEl.scrollTop` or call `scrollIntoView` on a chat list directly — use `stickToBottom(tab)`, `setScroll(tab, fn)` or `smoothScroll(tab, fn)`, and read `tab.followBottom` at the moment you need it instead of capturing `isNearBottom()` earlier. A new code path that inserts `.chat-msg` elements into the list needs nothing extra for scrolling (the MutationObserver registers them), but still needs `applyGrouping()`/`regroupFrom()`. The keeper corrects inside the ResizeObserver callback (scroll only, never element sizes) so no shifted frame is painted.
- Message DOM, grouping and the toolbar: see the root `AGENTS.md`'s "Message layout" paragraph. The rule to remember here: anything that adds or removes a `.chat-msg` must call `applyGrouping()`/`regroupFrom()` (the append, prepend and delete paths already do), and message actions go in `buildMessageActions()`/`insertToolbarButton()`, never back into the reaction strip.
- Invite codes (PRD 18.9): the connect form has a hidden `#invite-code` input. `startConnect()` passes it as `api.connect()`'s 4th argument ONLY when typed and never writes it to `localStorage`; the preload turns `res.errorCode` into the `error` event's `code`, and the `api.on("error")` handler reveals/focuses the field for `INVITE_REQUIRED`/`INVITE_INVALID`/`INVITE_THROTTLED`. `clearInviteField()` runs on `connected`. Moderator UI (User Management → Invites, `refreshInvites()`/`renderInvites()`) is built with `textContent`; the code reveal modal clears its text when closed.
- Attachments (`renderer.ts`, "Attachments: picking, uploading, the tray"): `pendingAttachments` is global, not per tab. `addFiles()` validates (image/*, ≤ 5 MB, ≤ 10 total, each refusal a toast — file names go through `escapeHtml` because `showToast` uses `innerHTML`), `pumpUploadQueue()` runs ≤ 3 uploads at once, and a card's object URL is revoked only when the card is removed or the send *succeeds*. `sendChatMessage()` clears the tray at once but keeps the batch; `restoreFailedBatch()` puts the cards back on failure (and on "no longer available" marks them failed so Retry re-uploads). `openLightbox(url, { previewOnly: true })` is the zoom-only viewer used for previews. `MAX_ATTACHMENTS_PER_MESSAGE` is mirrored locally because the renderer is a plain script that can't import shared-types — keep the two in sync.
- Replies: `replyTargets` (Map keyed by tab id), `startReply`/`cancelReply`/`renderReplyBar`/`syncReplyHighlight`; a snippet is built by `buildReplySnippet()` and updated live by `handleReplyOriginalDeleted()`/`refreshReplySnippets()`. The `chatInput` Escape handler runs the emoji autocomplete first, then reply cancel.
- Targeted DOM updates beat `renderTree()` for small state changes (the "viewing" highlight, channel muting): a full re-render loses collapsed-category state, which is also why `markChannelUnread()` avoids it.
- Per-user preferences added in Phase 16 (all `localStorage`, every access in `try/catch`): `reson8-nsfw-warning-dismissed` (`"true"` = don't warn; one global switch, not per channel), `reson8-nsfw-blur-images` (`"false"` turns the blur off via a `body.nsfw-blur-off` class, so already-rendered messages update live) and `reson8-muted-channels` (`{ [serverId]: channelId[] }`, pruned against the channel tree).
- Driving the real app headlessly (Phase 16 recipe — it caught many bugs typechecking could not): build with `npx tsc --build && node scripts/copy-html.mjs`, then run `xvfb-run -a env -u WAYLAND_DISPLAY electron . --no-sandbox --disable-gpu --user-data-dir=<tmp> --remote-debugging-port=<p>` so nothing appears on the real desktop and the single-instance lock can't collide with a Reson8 you have open (`--user-data-dir` matters). The renderer is a classic script, so its top-level functions and `let`/`const` state (`pendingAttachments`, `replyTargets`, `sendChatMessage()`…) are reachable straight from `Runtime.evaluate`. Feed `<input type="file">` a `DataTransfer.files`; synthesize `DragEvent`/`ClipboardEvent` with a real `DataTransfer`; hold or fail uploads with the CDP `Fetch` domain (pass `OPTIONS` through); use a fresh channel/user per run so old history can't leak into assertions; take `Page.captureScreenshot` and actually look at it. Stop it by the PID listening on the debug port — never `pkill -f` a pattern that also appears in your own command line, it kills your own shell.
- Phase 17 `localStorage` keys: `reson8-avatar-provider` / `reson8-avatar-email` / `reson8-avatars-external` (`"false"` = initials only) and `reson8-kept-tabs` (`{ [serverId]: channelId[] }`, tab-bar order). Message rendering paths take `{ stick: false }` for anything that isn't the live bottom (jump windows, newer pages) — see the root `AGENTS.md`'s "Chat pagination".
- Media proxy (PRD 18.19): `reson8-media` must be registered with `registerSchemesAsPrivileged` BEFORE `ready` (done at module top level in `main.ts`); `protocol.handle` runs inside `whenReady`. The renderer's CSP allows it in `media-src` only (not `connect-src`, so the page can't `fetch` it) — test the handler's status codes from the MAIN process (`--inspect`, `session.defaultSession.fetch`). `maybeProxyVideo()` rewrites a preview's `video` per IPC answer; the cached preview keeps the upstream URL. `test:media-proxy` covers the pure rules and the open-ended probe against local servers.
- Blurred previews (PRD 18.11): all four media branches of `createPreviewCard()` go through `wrapPreviewMedia()`; never reuse the attachment classes (`.msg-image-nsfw-*`). `syncTabNsfwClass()` runs from `openChatTab()` and `renderTree()`. `LinkPreviewData.adult` is client-only (not on the wire). `detectAdult()`/`extractNamedMeta()` live in the pure `link-preview-adult.ts` (covered by `test:link-preview`).
- Link previews (PRD 18.10): `reson8-link-previews` (`"false"` = off; checked first in `injectLinkPreview()` so nothing is requested, plus `body.link-previews-off` to hide rendered cards live). The renderer's `TtlCache` (300 entries, same TTLs as main) is a local copy because the renderer can't import modules; a `kind: "image"` result renders as a picture-only card that opens `openLightbox(url, { previewOnly: true })`.
- Anything persisted client-side uses `localStorage` with a `reson8-*` key prefix (grep for `reson8-` in `renderer.ts` to see the existing key namespace before adding a new one).
- TypeScript config (PRD 20 H2): the client compiles with `module`/`moduleResolution` `Node16` and `moduleDetection: "legacy"` (without it `renderer.ts` — a classic script with no imports — would be emitted as a CommonJS module and throw on `exports` in the browser). `@reson8/shared-types` is an ES module imported only as types, so each such import carries `with { "resolution-mode": "import" }`; a new type import of an ES-only package from a CommonJS file needs the same attribute. The emitted `dist/` is byte-identical to the previous `Node` resolution, so runtime behaviour (incl. the `dynamicImport` escape hatch below) is unchanged.
- Before adding an npm dependency consumed from `main.ts`/`preload.ts`/`voice.service.ts` (all CommonJS-compiled, per this workspace's tsconfig), check whether the package ships a real CJS build (`npm view <pkg> exports` — look for an actual `"require"` condition, and check there's no top-level `"type": "module"` silently overriding it). A `deepfilternet3-noise-filter`-style ESM-only package will crash the whole preload script at startup ("`ReferenceError: exports is not defined`") if statically imported — and a plain `await import(...)` isn't a safe workaround either, since this project's CommonJS module target rewrites dynamic `import()` back into a deferred `require()`, hitting the same crash lazily instead of at startup. The actual fix, only needed for genuinely ESM-only packages: `new Function("specifier", "return import(specifier)")` — invisible to TypeScript's static analysis, so it can't rewrite it — see `voice.service.ts`'s `dynamicImport` for the full pattern and reasoning. Prefer picking a dependency with a real CJS build (like `markdown-it`) over reaching for this trick when there's a choice.
- The `voice.service.ts` mic processing graph and preview mode (`startMicPreview()`/`getCurrentLevel()`) share the same `audioContext`/`analyser`/`gateGainNode`/`volumeGainNode` fields via a common `buildProcessingChain()` helper — preview mode builds the identical noise-gate/mic-volume/noise-cancelling chain a real call does, not just a bare analyser tap, so the mic meter, noise gate, and self-hear monitor all behave identically whether previewing or in a call. Sharing these fields is safe only because `joinVoiceChannel()` constructs a brand-new `VoiceService` per session, so a live call's graph and a pre-join preview never coexist on the same instance.
- Phase 19 renderer conventions (P1/P2 behaviour items; the visual overhaul comes later):
  - **Own permissions (A8):** `hasPerm(PERM.X)` returns `true | false | null` — `null` means unknown (an older server sends no permissions) and callers must then keep today's behaviour and let the server refuse. `PERM` mirrors `PermissionFlags` (the renderer is a classic script); keep the numbers in step. Menus are rebuilt per open, so `PERMISSIONS_CHANGED` needs no re-render.
  - **Server facts (A1/A7):** `getOnlineCountForDisplay()` is the ONE online count (header and About both call it); `api.getServerSummary()` / `api.getDmDirectory()` resolve `null` on an older server (5 s ack timeout) — always keep a fallback.
  - **Unread (B1–B3):** `unreadChannelCounts` / `unreadDmCounts` are Maps (`-1` = unread, number unknown, drawn as a dot). Seed only when there is no entry; `markChannelTabRead(tab)` is the ONE channel read path (active tab + window focus + page rendered) and `markDmTabRead()` the ONE DM path — never call `markChannelRead()`/`api.markDmsRead()` from a new view path. Muted channels keep counting but paint nothing (`applyChannelMuteState()` is a targeted update; do not `renderTree()` for it).
  - **Tabs (B4/B5):** `placeTab()`/`replaceablePreview()`/`insertTabElement()` are shared by `openChatTab()` and `openDmTab()`; a replaced preview must go through `closeTab(..., { reason: "replaced" })`. `openDmTab(userId, nick, { mode, focus })` defaults to preview + focus; anything automatic (incoming DM, connect-time unread) passes `{ mode: "kept", focus: false }`. Kept DM ids (`dm:<userId>`) share the kept-tabs store with channels and are restored by `restoreKeptDmTabs()` once DM data exists; the first channel tree arrives BEFORE the `connected` event, so such guards identify the server by `keptTabsServerId`, not `currentServerId`.
  - **Occupant menu (B8/B9):** `buildOccupantMenuModel()` returns data, `renderOccupantMenu()` draws it; the volume slider saves on `change`, never `input`; local mute/volume marks update through `refreshOccupantMarks(userId)` (no `renderTree()`). Kick is gated on `KICK_USER`.
  - **Updates (B12):** `updateState` + `setUpdateState()` are the single source of truth for the update modal, the About row and the gear dot; nothing restarts on its own (`Restart now` / `On next launch`).
  - **Test-script traps:** repeated `Runtime.evaluate` calls with a top-level `const` fail silently (use an IIFE); the headless window has real OS focus, so simulate an unfocused window by overriding `document.hasFocus` (and restore it).
  - **Menus (F3):** every context menu is a `MenuItem[]` passed to `openMenu(items, x, y, { anchor })` (one at a time; closes on outside pointerdown, Escape, blur, scroll, resize; keyboard Up/Down/Home/End; clamped with an 8 px margin). Never hand-build a menu element and never add `.ctx-*`-style CSS again. Icons are Phosphor classes (`ph-*`) from the vendored folder; Inter and Phosphor are vendored under `assets/` (no CDN).
  - **Saved servers (C1):** `reson8-saved-servers` (entries `{ id, address AS TYPED, name, nickname, iconUrl, iconThumb, hasPassword, lastConnected }`, max 50). The address is never re-serialised (identity proofs sign it without the scheme). Passwords live ONLY in the main process (`saved-passwords-store.ts`/`saved-passwords.ts`, `safeStorage`, reliable-backend rule); the renderer can `set`/`has`/`delete`, and `api.connect(…, savedServerId)` lets the PRELOAD read it at join time — the plaintext never reaches the renderer. `serverAvatarElement(name, url, size)` is the ONE server-avatar helper. The shell is `#titlebar` + `#shell` (`#rail`, `#welcome-screen`, `#main`); `body.is-connected` / `body.is-approving` decide welcome vs main. The connect inputs keep their ids (`#server-url`, `#nickname`, `#server-password`, `#invite-code`, `#remember-me`, `#btn-connect`); `#btn-disconnect` is a hidden control (disconnect lives in the server pill).

- **Icon cropping (PRD 19 C5):** both the channel-icon and the server-icon dialogs use ONE `IconCropper` class in `renderer.ts` (elements passed in; `.icon-crop-viewport/-img/-zoom` classes). Don't re-grow a second copy of the crop code. The server icon is validated client-side (type, ≤ 1 MB, ≥ 256×256) only for UX — the server re-checks the real bytes.

- **DM sidebar (PRD 19 C7):** the rail's DM button only toggles `#left-pane.show-dms` — the channel tree is hidden, never rebuilt. The list is `renderDmSidebar()`, fed by `api.getDmDirectory()` (older server: the online-users list, previews off) and kept live by `onDmMessageForSidebar()` / `onDmPresenceChange()`; anything that changes `unreadDmCounts`, the active tab or window focus must end in `scheduleDmSidebarRender()` (it already does via `refreshTabUnread`, `switchTab` and the focus/blur handlers). The rail total excludes the conversation being read. The old Online Users modal is gone — don't re-add a second way to list people.

- **Tab bar overflow (PRD 19 C8):** `layoutTabBar()` is the only place that decides which tabs show; it changes `display` (`.tab-hidden`) and `order` only — never move tab elements (the DOM order IS the kept-tabs order) and never set a width there. A change that alters a tab's width (label, badge, icon, weight) must call `invalidateTabWidth()` (the existing helpers already do). New tab elements go through `insertTabElement()` so the overflow button stays last.

- **Voice room tab (PRD 19 C9):** `voiceTab` is its own object, not a `ChatTab` — never route it through chat-only machinery (`chatTabs`, scroll keeper, unread). It is opened by `openVoiceTab()` and closed ONLY by `closeVoiceTab()`, which `updateVoiceUI()` calls whenever you are not in voice (so a kick or a deleted channel needs no extra code). Tiles are keyed by user id and updated in place; a speaking change is a class toggle through `speakingEls()` (tree rows and tiles), never a rebuild. A new place that draws an occupant must offer the shared menu via `renderOccupantMenu(buildOccupantMenuModel(...))`.

- **Stream stage and Viewer (PRD 19 C10):** the receive pipeline exists ONCE, in `src/screen-watch.ts`, used by the main preload's `api.stage` and by `preload-viewer.ts` — never re-grow a second copy. A primary socket must never call WATCH/STOP_WATCHING (V27); the stage uses its own `role: "viewer"` socket. The renderer's `stageState` machine is the only owner of "who is consuming": every transition `await`s the previous side closing, so there are never two consumers; clicks are ignored while `starting/popping/returning`. The ticket never reaches the renderer. Any new teardown path (access, room, disconnect, sharer gone, tab closed) must end in `stopStageWatch()`, which also closes a popped Viewer. The Viewer is controlled only through ids `main.ts` recorded in `viewerWindows`.

- **Several streams (PRD 19 C11):** `api.stage` is keyed by sharer id. Focus = ONE main watch (`stageTarget`) + static cards (no consumers); Grid = `gridCells`, one muted watch per sharer. Both are torn down by `stopStageWatch()`; Grid cells are kept in step with presence by `syncStreamGrid()` from `renderVoiceRoom()`. Live previews on the cards need the viewer-socket event `SET_CONSUMER_LAYERS`; the owner decided to keep static cards (PRD 20 D1 = b) — do not add them without a new decision.

- **Updates UI (PRD 19 C12):** the corner card, the About row, the gear dot and the What's new dialog are all views of ONE `updateState` (`setUpdateState()` → `updateListeners`); never write update text anywhere else. There is no update modal. What's new has three variants through `showWhatsNew()` — only "launch" marks a version seen.

- **Window-button safe area:** the OS buttons are drawn OVER the page with a TRANSPARENT background (`TITLEBAR_COLOR` in `window-chrome.ts`, like Discord). The app keeps out of them through three body-level tokens in `index.html`: `--titlebar-h` (the band, 0 when the system frame is used or in fullscreen), `--controls-right` (button width, from `env(titlebar-area-*)`) and `--controls-left` (macOS traffic lights). Rules: a full-window dialog wrapper gets `padding: var(--titlebar-h) 0` (the same gap above and below, so it stays visually centred) and any `calc(100vh - …)` size on its content subtracts `2 * var(--titlebar-h)`; full-bleed media (the image viewer) keeps its controls at the right edge but one row BELOW the band (`top: calc(var(--titlebar-h) + 8px)`), and any control there needs an opaque pill background so it can't be mistaken for a window button; fixed corner UI (toasts) starts under the band. A NEW full-window overlay or top-right fixed element must follow the same rule.

- **Phase 20 renderer conventions:**
  - **Menus:** `openMenu()` also takes `placement: "above"` (bottom-of-sidebar anchors), `align: "center"` and `minWidth`; a press on a menu's own anchor closes it (anchors toggle) — don't add a separate toggle handler.
  - **Audio devices (U1):** `applyAudioDevice()` is the ONE place a device is applied and remembered (Settings' Save and the dock/call-bar carets); read every staged value before the first call (it re-populates the Settings lists).
  - **Call bar (U2):** the voice room's call bar has no state; `renderCallBar()` mirrors the dock. Add new call controls the same way.
  - **Settings nav counts (M4):** `updateSettingsNavCount(page, n, show?)` — reset on disconnect.
  - **Typing (W2):** `reson8-send-typing` (`"false"` = never send); one signal per 3 s while the composer has text; the line shows only for the active tab and entries expire after 5 s or on that person's message.
  - **Search (Q1):** results are built with `textContent` and `<mark>` from split text — never `innerHTML` of server text; a result click opens the tab, waits for its first page, then `jumpToMessage()`.
  - **Saved-server latency (W1):** probes run only on the welcome screen (stopped on connect) through the main process (`probe-server-latency`, the pinned-certificate session) — never `fetch` a server from the renderer.
  - **Phosphor:** only the regular and fill weights are vendored; `ph-bold` draws nothing.

- **Integrated title bar (PRD 19 R7):** both windows get their frame from `frameOptions()` in `src/window-chrome.ts`; the mode is decided by the main process at startup (`window-chrome.json`, "Use the system title bar") and the page only reads it (`body.integrated-titlebar`). `#titlebar` is a drag region: anything clickable inside it, and ANY new element that can float over the top 38 px (`position: fixed` menus, popovers, cards), must be `-webkit-app-region: no-drag` or its clicks silently drag the window.

- **Settings modes (PRD 19 R3):** `#admin-modal` is ONE left-nav dialog with two modes, `data-mode="client"` (the gear: `openClientSettings(page?)`) and `"server"` (the header menu: `openServerSettings()`). A page belongs to a mode through its nav button's `.settings-nav-group[data-nav-mode]`. `openSettingsPanel()` refreshes the data and is safe to call again (role changes do) — it never changes the mode. Add a new page as a `.settings-tab-btn` in the right group plus a `.settings-panel[data-settings-panel]` with a `.settings-page-title`, and put rows inside `.settings-section > .settings-card`.
