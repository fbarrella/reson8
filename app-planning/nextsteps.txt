- feat: enable setting up avatars (maybe using gravatar)
    Let's make the app a little bit more fun! We've been through a lot to make the app robust and trustful, now let's add some features to level up the user experience in the playful way. Let's implement avatars for users in the app. To make this possible, let's use a "gravatar" like solution, called "Libravatar" from 'libravatar.org'. The tool api documentation is contained on the link: 'https://wiki.libravatar.org/api/'. But it is really easy to use. Before anything we, of course, must warn the user that for him to customize its avatar he must create an account on the libravatar platform with its email and then upload the avatar on that site. Then we can setup the logic: Firstly, we must ask to the user to fill an input with its email in order to retrieve the avatar correctly. Then, we must hash the email to SHA256. Finally, we get the base url 'https://seccdn.libravatar.org/avatar/', concat with the hashed email and, finally, concat with the fallback avatar parameter '?d=wavatar'. The final result is the url for the image resource. This is the one that will be used throughout the entire app, into the places to be defined. But of course, we must show the avatar right on the configuration section first, so the user can see if it worked. This whole configuration is purely client based, since this an avatar related to the user in general, so the server doesn't need to know that. Because of that the section should be located on the "Application" tab on the settings screen. It should be a whole profile configuration settings. To correctly use these avatars through the app, we'll need to associate the avatar extracted URL to the client ID. But even though the it is client based, to avoid breaking avatars whenever a user disconnects, the server will store the latest fetched url for that user (again, via its client id). The server will check for the user avatar url once when it logs in, and will store it to keep using it if it disconnects. If the user updates its avatar settings, the client id will send a warning asking for the server to update this avatar info. All of the logic for the libravatar works for gravatar, but, of course, changing the url extraction logic a little bit. Make sure we'll have gravatar implementation as an second option for the user to choose where it wants its avatar from. He should a selector to make the choice, also on the profile config section. Of course, when the avatar feat first go up, no one will have seteup its own avatars. So, we will use the default random avatars url from libravatar as an default. To do that we must just use the base path 'https://seccdn.libravatar.org/gravatarproxy/', concatenated with the respective user id, and finally concatenated with the parameters '?s=80&default=wavatar'. This is all we need for this implementation. - feature: only keep 'fixed' chat tabs opened, the not fixed will promptly be substituted by the next opened chat
    This is another quality of life improvement: currently, everytime we one-click a text channel, it opens it as a new tab. If i single click 12 text chats, there will be 12 tabs opened. On bigger servers this is bad because then after the user will have to click every single "x" button to close the tabs. This is not really handy at all. To avoid this problem, we'll change the text channel opening behaviour a little bit. Instead of opening a new tab for every single click, we'll use an approach similar to what vscode does at default: if you click a file, it opens, but it doesn't fixes the opened tab. This makes so, if you click another text channel it will close the previous file tab and open the tab for the now clicked channel. This will be the default behaviour: tabs will not accumualte. Different from vscode, a double click to a text channel won't do any difference. It will still have the chat opened on a tab only untill the user clicks another channel, then the tab it will be promptly substituted by the tab for the recently clicked one. But there will still be a way to have more than one tab open! A feature to "fix" the tab open! If the user desires to have a tab that doesn't close, it must right click the tab and choose "Fix channel". Then, this tab won't be substituted anymore, instead, will be kept open while the volatile tabs will be happening only to the rest of the channels. This "fix channel" feature should also appear on the right click menu for the text channels! This whole fix and volatile behaviours will only be applied into text channels. Direct messages tabs will keep behaving the same way it always did. - feat: implement 'fixers' to rich context metadata for social media links
    Currently the app has a really great way of dealing with extracting rich metadata content (such as author, title, media, etc). But sometimes, some social networks that relies mostly on video, when we share the link for one of said videos, we only get the thumbnail for the video as a link, being forced to open the link on another app to really consume the shared content. This happens even with the fallback for the crawler. So, some devs over the internet developed fixes for this. It started with FxTwitter that started to enhance the attached metadata with the url, and then it quickly spread to other social medias. So, we'll use this to our advantage. These fixes simply work by replacing the base path of the social media links with the respective 'fx' base path, and then the rest is done by a proxy server. So, we'll have a limited set of urls for a limited set of social medias. The links that are not contained in this list will work just as it does before this new implementation. First, try to extract metadata from the link, and if it doesn't work properly, fallback to the crawler. For the links mapped to fx solutions, there will be 3 tries. First one will be directly with the mapped fx solution for the specified social media. Then, if this one doesn't works out (for rare cases that the proxy server stopped working), the traditional flow will be followed just as it is done for the links out of the mapping scope, with its entirety acting like a fallback. The list of social medias and its respective fx solutions are as follow: 1) Youtube - 'koutube.com'; 2) Twitter or X - 'fxtwitter.com'; 3) Instagram - 'oginstagram.com'; 4) Reddit - 'vxreddit.com'; 5) Twitch - 'fxtwitch.seria.moe'; 6) Bluesky - 'vxbsky.app'; 7) Imgur - 'imgurez.com'. That is it.
