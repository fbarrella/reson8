- chore: chat loading should be paginated on the backend and it should load dynamically as the user scrolls up to see past messages;
    Text chats are currently being open with its full content getting loaded at once. This is ok when the text chat is small and have a really low count of entries. But as soon as times goes by and the text chat starts to be used and get more and more entries, load all of its content at once can make so the server and the database gets overloaded without really needing it, since the user screen can only show a few messages on screen. So, to improve this and future proof the application, let's make so text chats api calls are paginated and the frontend loads chunks of the chat on demand. So, for instance, the chat starts with the latest 20 messages, from the entire history, loaded. Then, it's when the user scrolls all the way to the top and hits the last message of the current chunk, the the frontend understands this action and automatically starts to fetch the next chunk of messages. To the user, this must feel seamless. Also, since we're loading the messages with pagination and we want to present them to the user in a similar way that we currently do right now, don't forget to make the needed adjustments. Before implementing anything, be sure to investigate into the already existing code for the text chats (and all of this serves both to text channels and DM's) and also be sure to understand the best practices to do so.
