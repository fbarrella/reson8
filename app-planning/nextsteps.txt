- feat: implement noise cancelling
    The DeepFilterNet (https://github.com/rikorose/deepfilternet) noise cancellation feature will introduce an AI-driven toggle, inside the voice configuration tab on the setting screen, to suppress background disturbances, such as mechanical keyboard clicks and fan noise, while preserving crystal-clear voice transmission. This functionality requires a dedicated UI toggle switch located directly within the Audio Settings tab. It should be positioned alongside the existing global voice chat volume and mic sensitivity sliders. To ensure a seamless user experience, the system must persist the selected on/off state across application restarts utilizing localStorage.  Under the hood, the architecture leverages a WebAssembly (WASM) build of DeepFilterNet instantiated within an AudioWorklet. This isolates all real-time audio mathematics on a background thread, completely preventing UI stuttering in the React renderer. The audio pipeline intercepts the user's raw MediaStream from getUserMedia right before it is passed to startProducing(). The routing graph will flow from the microphone input into an AudioContext, through the AudioWorkletNode, and finally into a MediaStreamAudioDestinationNode. Crucially, the existing AnalyserNode powering the live mic sensitivity meter must be re-routed to tap into the audio graph strictly after the AudioWorkletNode. This ensures the live meter provides accurate, real-time visual feedback of the processed, noise-free audio output rather than the raw hardware input. The cleanly processed MediaStreamTrack is then extracted and supplied directly to the active mediasoup Producer for transport.  To avoid audible popping or dropped communication, toggling the filter must never tear down the existing Web Audio graph or the mediasoup WebRTC connection. Instead, flipping the UI switch will send a postMessage containing the new boolean state directly to the running AudioWorklet. When the filter is disabled, the worklet's process() function shifts into a raw passthrough mode—bypassing the WASM engine entirely and copying input buffers directly to output buffers to instantly release CPU overhead. Finally, the electron-builder configuration must be explicitly updated to include the DeepFilterNet .wasm binary. This ensures it is correctly mapped in the files array or added to asarUnpack so the React renderer can access it reliably in production deployments. Be careful on this implementation. Investigate the existing codebase to avoid breaking pre-existing code and be sure to use best practices while implementing it.
