- Reson8 Client
    - [HIGHEST PRIORITY][FIX] "Voice chat participants randomly getting disconnected from the channel" - There is currently an intermitent problem happening occasionally where a random voice chat participant gets disconnected from the voice channel. It doesn't happen often but it does happen sometimes and in these times the experience feels cheap and bad. Investigate thoroughly the whole voice channel logic and find if there are any gaps on the current implementation that could result in a problem like the one described, and also once we're already checking the codebase, map any possible codesmells and bad practices. We need to fix this problem if possible and also use the best existing practices for voice chat apps like the one we have here.
    - [FIX] "Voice channel session timer is currently starting from negative numbers" - Currently, whenever I join any voice channels on the app, the session timer starts at something like minus two minutes or minus one minute and then goes up one by one until it finally starts counting from positive numbers. Investigate the possible cause and fix this.
    - [FIX] "Emoji picker hasn't enough space for the 'custom emojis' tab" - The "plus sign" used as an icon to signal the custom emojis tab into the emoji picker isn't visible most of the time, so the only way to access the section is by scrolling all the way to the bottom. First of all, the current plus sign used was the emoji plus sign, let's replace this by an more elegant svg icon similar to the "add emoji" button, but in a smaller form to fit the tab. Then, adjust the emoji picker sizing to make the cutsom emojis tab be always accessible. Use UI best practices while doing it.
    - [IMPROVEMENT] "Show a modal containing new release info and a link to the github page once after a update" - Whenever the Reson8 client is opened for the first time after an update, a modal containing the new release information should be shown (the release text from the release page), a link directing the user to the github page to see more, and a button to dismiss should be shown to the user once. When the user click the dismiss button, then the modal should not appear anymore. Then, another modal will only show after the next update and it will follow the same logic of not appearing anymore after a dismissal.
    - [NEW FEATURE] "Admin should be able to pin messages into text channels" - Admins should be able to pin a message (and one message only) on a text channel. Each text channel can have its own pinned message. The UI should show the pinned message on the top of the chat in the form of a bar, with a svg pin icon before the text. The content of the bar should be just a cropped section from the original message and when a user clicks the bar, it should place the user chat directly onto the original message, with a little highlight on it. Be carefull while implementing it because these UI alterations might brake something on the original voice chat experience and we don't want that. Also, remember to always check for best practices while elaborating new features.
