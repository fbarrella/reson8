# 🎧 Reson8 v2.7.0 Release Notes

This release is about trust and control: connections can be encrypted and pinned, you can decide who gets in (approval, invite codes, address bans), removing the Member role really restricts someone, and link previews are safer, steadier and better behaved. It also fixes a way for anyone connected to take a server down.

> **Please update the server and the clients together.** A v2.6.0 client still works with a v2.7.0 server (with the exceptions below), and a v2.7.0 client still works with an older server.
>
> **Server admins — please read:**
> - This version adds database migrations (identity log, address bans, approval requests, invites, and a membership backfill). Docker deployments apply them automatically on start; otherwise run `npx prisma migrate deploy` in `apps/server` before starting the new server. Nothing existing is changed or deleted.
> - **Everything new about who gets in is OFF by default:** *Approve new users*, *Require an invite code*, and address bans are switches/options in Settings; a server upgraded to v2.7.0 behaves like before until you turn them on.
> - **Removing the Member role now restricts the user.** Until now it was quietly given back on the user's next connect. From v2.7.0 it sticks, and the user can't open text channels, send or read DMs or join voice until you give it back. People who already have Member keep it; nobody loses access on upgrade.
> - **If a reverse proxy is in front of your server, set `TRUST_PROXY`** (for example `TRUST_PROXY=loopback, uniquelocal`). The server now only believes forwarded addresses (`X-Forwarded-For`, `CF-Connecting-IP`) from proxies you list; without it, address bans and the identity log see the proxy's address (address bans will refuse to ban a private address in that case, with an explanation). The Caddy override in the repo sets it for you.
> - **Encrypted connections:** set `TLS_CERT_FILE` and `TLS_KEY_FILE` to serve HTTPS/WSS directly, or put a reverse proxy in front (a Caddy recipe is included). A v2.6.0 client can't connect to a server that *only* speaks HTTPS — update those clients.
> - Optional but recommended: turn on **Require signed identity** in Settings → Server once everyone has updated.

## ✨ New Features & Improvements

- 🔒 **Encrypted Connections** — The client now tries HTTPS first. If a server uses a self-signed certificate you're shown its fingerprint and can choose to trust it; from then on Reson8 only connects while it presents exactly that certificate (a changed certificate is refused until you remove the trust in Settings). A lock in the status bar shows when you're encrypted and a clear "Not encrypted" notice when you aren't.
- 🛡️ **Server-Side HTTPS and Proxy Support** — The server can serve HTTPS directly (certificates reload without a restart) and understands the address a reverse proxy forwards, only from proxies you trust.
- 📜 **Identity Log** — Admins can open **Settings → User Management → Identity log** to see key binds, key resets and refused sign-ins (with the reason and, for admins, the address), and per user with the small log button on each row.
- 🔑 **"Require Signed Identity" Switch** — Refusing older, unsigned clients is now a switch in Settings → Server, with a count of users who still have no protected identity (an environment variable still wins and locks it).
- 🌐 **Connection Names in Settings** — The list of names a sign-in may be addressed to (the relay protection) is managed in Settings → Server, suggests the names it has actually seen, and refuses to save a list that would lock you out.
- 🗝️ **Your Identity Key, Safer** — The key is now stored encrypted by your operating system where that's reliable, and **Settings → About** can export it to a passphrase-protected backup file and import it on another computer. If the key can't be unlocked you get a clear message instead of a silent new identity.
- 🚫 **Address and Range Bans** — When banning someone you can also ban their address or its surrounding range (off by default: a VPN gets around it and a shared network can catch innocent people). Lifting the user ban lifts it too, and the list is in User Management.
- 🚪 **Approve New Users** — An admin can switch on approval: people who have never joined wait on a screen with their key fingerprint until a moderator approves them (a badge shows how many are waiting). Moderators can approve, reject, or reject and ban.
- 🎟️ **Invite Codes** — An admin can require an invite code for new users. Moderators create codes in User Management → Invites (label, expiry, maximum uses), see who came in with each one and can revoke them. A code is shown once; wrong guesses are rate-limited. Works together with approval.
- 🚷 **Removing Member Restricts Someone** — Users without the Member role stay connected but can't use channels, DMs or voice; it takes effect live (and is undone live), with a banner explaining why. User Management tags them "No access".
- 🧑‍🤝‍🧑 **Role-less Members Stay Listed** — Users who lost all their roles no longer disappear from User Management, so you can give a role back or ban them.
- 🔗 **Safer, Lighter Link Previews** — Previews no longer reach into your own network (no requests to private or local addresses, even through redirects), read only the top of a page, time out properly, expire from the cache, and show direct image links as pictures. **Settings → Application → Show link previews** turns them off entirely.
- 🫣 **Blurred Link Previews** — Preview pictures and videos are blurred (click to reveal) in NSFW channels and wherever a website itself marks a page as adult, each with its own switch in Settings → Application.
- 🎬 **Preview Videos Go Fullscreen and Seek** — Videos in link previews can go fullscreen from their own controls, YouTube previews can jump forward and back, and clicking a preview picture opens the zoom-only image viewer.
- 🔴 **DM Unread Dots and "See More"** — Open DM tabs you aren't looking at show the same red dot as channels, a DM only counts as read once its tab is open in a focused window, and long DMs collapse behind "See more".
- 🧱 **Chat Stays Put While Things Load** — Opening a busy channel or reading history no longer drifts or jumps while previews and images load; if you're at the bottom you stay at the bottom, and if you've scrolled away nothing moves under you.
- 🏷️ **Same "Category" Badge Everywhere** — Every channel that has sub-channels shows the "Category" label, text or voice.
- 🧼 **Centered About Page** — The app description in Settings → About is centered.

## 🐛 Bug Fixes

- 🛑 **A Way to Crash the Server Is Closed (Security)** — Any connected client could take a server down by sending an event without a callback, and a few requests (reading a channel's history, joining a channel's live room) answered clients that had never signed in. Every event now passes one default-deny gate.
- 🐦 **X/Twitter Videos Play Again** — Links to posts with a video on x.com / twitter.com show the video in the chat again (the preview service hid the media from the identity we were asking with).
- 🔗 **Previews Can't Probe Your Network (Security)** — See Safer, Lighter Link Previews above: a posted link can no longer make your computer contact a device on your home network.
- 🧹 **Working Lint** — `npm run lint` now actually runs (developers).
