PROJECT OVERVIEW
================
Reson8 is a high-performance, self-hosted voice and text communication platform
for desktop (Electron). It replicates the TeamSpeak 3 experience — low-latency
voice, hierarchical channel trees, and private server ownership — while
integrating modern persistent text channels.

Tech Stack: Electron + TypeScript, Fastify + Socket.io, mediasoup (SFU),
PostgreSQL + Prisma, Redis, Docker.

Monorepo structure:
  apps/client/            — Electron desktop client
  apps/server/             — Node.js signaling + SFU server
  packages/shared-types/    — Shared DTOs, enums, and Socket.io event types

For build commands, environment variables, ports, and architecture details,
see the root CLAUDE.md (and apps/client/CLAUDE.md, apps/server/CLAUDE.md) —
not duplicated here to avoid drift between docs.

Feature/Fix: PRD 17.1 — Avatars via Libravatar/Gravatar (profile settings + server storage)

  Problem: Reson8 had no avatars at all. Users wanted a picture identity
  hosted on Libravatar (default) or Gravatar, chosen by email, that other
  users can see even while its owner is offline.

  Solution: Settings -> Application has a new first section, "Profile":
  an avatar source switch (Libravatar | Gravatar), an email field, a 96px
  live preview and Save/Remove buttons, plus a "Load avatars from
  Libravatar/Gravatar" opt-out toggle (user decision; off = colored
  initials, no external requests at all). The email is hashed locally
  (SHA-256 of the trimmed, lower-cased address, the key both providers
  use) and only { provider, hash } is ever sent to the server. The server
  NEVER accepts a URL: it validates the selection and builds the URL from
  one of two fixed templates, so a modified client can't make everyone
  load an image from a host of its choosing (an IP-logging pixel), the
  same principle as the PRD 16.8 upload ledger. The stored URL is
  refreshed on every USER_JOIN_SERVER ("checked once at login") and via a
  new SET_AVATAR event when changed while connected; changes are broadcast
  as USER_AVATAR_UPDATED. Users without an avatar get Libravatar's
  generated "wavatar" keyed by sha256(userId), never the raw id, because
  the user id IS the instanceId, the identity credential (user decision).

  Shared Types Changes:
    - AvatarProvider ("libravatar" | "gravatar"), IAvatarSelection
      { provider, hash }; IUser.avatarUrl?.
    - USER_JOIN_SERVER payload gains avatar?: IAvatarSelection | null.
      Absent (a v2.5.0 client) = leave the stored avatar alone; null =
      clear it; an object = validate and store.
    - New C2S SET_AVATAR ({ avatar } -> { success, avatarUrl?, error? }).
    - New S2C USER_AVATAR_UPDATED ({ userId, avatarUrl | null }).

  Database Changes:

Feature/Fix: PRD 17.4 — Microphone volume up to 300% (with a soft clipper)

  Problem: Settings -> Voice & Shortcuts -> Microphone Volume stopped at 200%;
  the user wanted 300%. At 3x digital gain a normal voice easily exceeds
  full scale, and the Opus encoder would receive hard-clipped (harshly
  distorted) samples.

  Solution: The slider goes to 300%, and a soft clipper was added as the
  last stage of the shared send-side chain:
    micSource -> [noiseCancel] -> gateGain -> volumeGain -> softClip ->
    destination / self-hear.
  At or below 100% the clipper is BYPASSED (WaveShaper curve = null, a
  pass-through by spec), so the signal is exactly what it was before.
  Above 100%, loud peaks bend smoothly toward a 0.99 ceiling instead of
  clipping.

  Design Notes (why it's built this way):
    - A WaveShaperNode clamps its INPUT to [-1, 1] before applying the
      curve, so a x3 signal would already be hard-clipped before the curve
      saw it. The gain is therefore folded into the curve: above 100% the
      volume GainNode applies volume/3 (keeping the shaper's input inside
      [-1, 1]) and the curve maps x -> softClip(3x). In the linear region
      the effective boost is exactly the chosen volume.
    - softClip(): identity up to 0.8 of full scale, then a tanh knee
      approaching the ceiling, continuous with slope 1 at the knee (no
      audible corner). WaveShaper rather than DynamicsCompressorNode: no
      look-ahead latency (the compressor adds ~6 ms to voice).
    - oversample "2x" when engaged (no aliasing from the knee), "none" when
      bypassed.
    - Ceiling 0.99, not 1.0: measured in Chromium, the 2x oversampling
      filter overshot a full-scale input at 300% to 1.0002 with a 1.0
      ceiling. 0.99 (~-0.09 dBFS) leaves that headroom, as limiters
      normally do.
    - The curve (4097 points, odd so x=0 is a point) is built once and
      shared.
    - Built inside the shared buildProcessingChain(), so preview mode and a
      real call stay identical (apps/client/CLAUDE.md). The produce
      destination and the self-hear monitor now tap softClipNode, so Hear
      Yourself plays exactly what is sent. The level meter tap is unchanged
      (post-noise-cancel, pre-gate).

  Client Changes:
    - services/mic-soft-clip.ts (NEW, pure): MIC_VOLUME_MAX_GAIN = 3,
      SOFT_CLIP_KNEE = 0.8, SOFT_CLIP_CEILING = 0.99, softClip(),
      buildSoftClipCurve(), micVolumeStages(volume) -> { gain, clip }
      (clamped to 0-3; NaN -> 100%).
    - voice.service.ts: softClipNode (created, connected and torn down with
      the chain); applyMicVolumeStages() sets the gain/curve/oversample from
      micVolume, on build and on every setMicVolume() (clamp 0-300, NaN ->
      100); self-hear and the produce destination tap softClipNode.
    - index.html: slider max 300; description adds "Above 100%, loud peaks
      are softly limited instead of distorting."
    - renderer.ts: the stored reson8-mic-volume is clamped to 0-300 on load
      (a non-number falls back to 100), so a corrupt value can't become a
      NaN/huge gain.

Feature/Fix: PRD 17.10 — Keep whitespace-only lines as blank lines in Markdown

  Problem: There was no way to show a blank line between paragraphs
  (useful for warning-style messages). A line containing only spaces, typed
  as Shift+Enter, space, Shift+Enter, was treated by markdown-it exactly
  like an empty line: a paragraph boundary, and paragraphs render with no
  visible gap. Confirmed before changing anything: "Line 1\n \nLine 3"
  and "Line 1\n\nLine 3" produced identical HTML.

  Solution: renderMessageMarkdown() now runs preserveWhitespaceOnlyLines()
  before parsing. Every line made only of spaces/tabs (at least one) becomes
  a single U+00A0 no-break space, which markdown-it treats as ordinary
  paragraph text, so with `breaks: true` it renders as one visible blank
  line (`<br>\n&nbsp;<br>`), and several in a row stay several. A truly
  empty line is left alone (still a plain paragraph break, as nextsteps
  allows).
  - Fenced code blocks are untouched: their whitespace is content. Fences
    are tracked per CommonMark (``` or ~~~ with up to 3 leading spaces;
    closed by the same character at least as long with nothing after it; a
    backtick fence's info string can't contain a backtick).
  - Inside a quote or a list item the blank line stays within that block
    and the quote/list continues.
  - markdownToPlainText() (pinned bar, reply snippets) needed no change:
    it collapses all whitespace, NBSP included.
  - The pipeline already allowed it: the client and server only trim the
    WHOLE message and normalizeNewlines() leaves inner lines alone (checked
    end to end below). No server change.

Feature/Fix: PRD 17.12 — Cryptographic identity (stop instance-id impersonation)

  Problem (audit finding, added to Phase 17 at the user's request): a user
  WAS whatever `instanceId` a socket presented at USER_JOIN_SERVER, and
  every id is broadcast to every client (USER_JOINED, presence, message
  DTOs), so anyone could join as anyone, the admin included. One install
  uses the same id on every server, so any server operator (or anyone
  sniffing plain ws://) learned an id usable everywhere else. Worse,
  VIEWER_AUTHENTICATE accepted any id with NO password or ban check, so an
  outsider could watch a channel's screen shares using an occupant's id.

  Solution: public-key challenge-response (the SSH/WebAuthn model), Ed25519
  via Node's built-in crypto on both sides (no new dependency).
  - Each install has a key pair whose private key never leaves the Electron
    MAIN process.
  - On every connection (reconnects included) the server issues a fresh
    single-use nonce (60 s); the client signs
    "reson8-auth-v1\n<nonce>\n<host>"; the server verifies against the key
    BOUND to that id.
  - Trust on first use: the first valid signed join binds the key, via an
    atomic compare-and-set, so racing first joins can't both win.
  - User ids stay the same; they are now treated as public handles.
  - A secret token was rejected: every server would learn it and could
    replay it elsewhere.
  User decisions: in this phase as 17.12; gradual rollout (bound
  identities are protected at once, unbound legacy joins are allowed until
  REQUIRE_SIGNED_IDENTITY=true); optional ADMIN_KEY_FINGERPRINT; an
  ADMIN-only "Reset key" in User Management for recovery.

  Database Changes:
    - Migration 20261011120000_add_user_identity_key: users."publicKey"
      TEXT and "publicKeyBoundAt" TIMESTAMP(3), both nullable, no backfill.

  Shared Types Changes:
    - New events: REQUEST_AUTH_CHALLENGE, REQUEST_VIEWER_TICKET,
      RESET_IDENTITY_KEY.
    - USER_JOIN_SERVER.identity?: { publicKey, signature, host };
      VIEWER_AUTHENTICATE payload { ticket?, instanceId? }.
    - GET_ALL_USERS rows: hasIdentityKey?.
    - SocketData: authNonce?, authNonceIssuedAt?.

  Server Changes:
    - services/identity.service.ts (NEW, pure + node:crypto): nonce,
      authMessage, parseIdentityProof (shape checks), Ed25519-only key
      import, verifyAuthSignature, SSH-style keyFingerprint, isNonceFresh,
      isHostAllowed, and decideIdentity(), the PRD's table as one pure
      function:
      - signed + same key → accept; signed + other key → refuse "registered
        to another device"; signed + unbound → accept + BIND; invalid
        signature or disallowed host → refuse;
      - unsigned + bound → refuse "protected — update"; unsigned + unbound
        → accept unless REQUIRE_SIGNED_IDENTITY, or the admin id with a
        fingerprint set;
      - the admin role is only granted when no fingerprint is set or the key
        matches it, and a foreign key can never bind a fingerprint-protected
        admin id.
    - config/identity.config.ts (NEW): REQUIRE_SIGNED_IDENTITY,
      ADMIN_KEY_FINGERPRINT, AUTH_ALLOWED_HOSTS, read at call time.
    - connection.handler.ts:
      - REQUEST_AUTH_CHALLENGE.
      - USER_JOIN_SERVER: validates instanceId; the identity decision runs
        after the password/ban checks and BEFORE any write; the nonce is
        taken from the socket (never the payload) and consumed whatever the
        outcome; binding is a CAS (updateMany ... WHERE "publicKey" IS NULL)
        for an existing row, or the key is set in the upsert's create for a
        new user, with race checks; role-admin is granted only on
        decision.grantAdmin. Every bind/refusal is logged with fingerprint,
        address and host (never the signature).
      - REQUEST_VIEWER_TICKET: only the owning primary socket.
      - VIEWER_AUTHENTICATE now takes the user id FROM THE TICKET. The legacy
        id path is allowed only for an unbound id, while unsigned joins are
        allowed, AND while that user has a live owned session.
      - finalizeDisconnect revokes the user's viewer tickets.
    - services/viewer-ticket.service.ts (NEW): the upload-token pattern —
      32 random bytes, only the SHA-256 stored in Redis, 10 min TTL

    - admin.handler.ts: RESET_IDENTITY_KEY (requirePermission ADMIN) clears
