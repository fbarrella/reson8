PROJECT OVERVIEW
================
Reson8 is a high-performance, self-hosted voice and text communication platform
for desktop (Electron). It replicates the TeamSpeak 3 experience — low-latency
voice, hierarchical channel trees, and private server ownership — while
integrating modern persistent text channels.

Tech Stack: Electron + TypeScript, Fastify + Socket.io, mediasoup (SFU),
PostgreSQL + Prisma, Redis, Docker.

Monorepo structure:
  apps/client/      — Electron desktop client
  apps/server/      — Node.js signaling + SFU server
  packages/shared-types/  — Shared DTOs, enums, and Socket.io event types

Deliverables:
  - mediasoup SFU integrated into the Node.js backend
  - Full WebRTC handshake: 6-step signaling flow
  - Two-way audio: two users in the same room can hear each other
  - Mute/Unmute and Deafen/Undeafen controls
  - Voice control tooltips for better UX

6-Step WebRTC Handshake:
  1. GET_ROUTER_CAPABILITIES — client gets Router's RTP capabilities
  2. CREATE_WEBRTC_TRANSPORT — client creates send + recv transports
  3. CONNECT_TRANSPORT — DTLS handshake for each transport
  4. PRODUCE — client starts sending mic audio
  5. CONSUME — client receives remote audio
  6. RESUME_CONSUMER — consumer starts paused, client resumes after setup

Key Files:
  apps/server/src/services/mediasoup.service.ts — Worker pool, Router/Transport/Session management
  apps/server/src/config/mediasoup.config.ts    — Worker, Router, Transport settings (Opus codec)
  apps/server/src/handlers/voice.handler.ts     — All 6 signaling events + CLOSE_PRODUCER

--- Entry: 16/03/2026 ---

Feature/Fix: PRD 2.1 — Dual Channel Connection Bug Fix

  Problem: Users could appear in two voice channels simultaneously when
  rapidly clicking between channels. The USER_JOIN_CHANNEL handler left the
  old Socket.io room but did NOT clean up mediasoup sessions, emit
  PRODUCER_CLOSED to old-channel peers, or broadcast a PRESENCE_UPDATE
  for the old channel.

  Server Fix (connection.handler.ts):
    - USER_JOIN_CHANNEL now performs FULL cleanup of the previous channel:
      1. Retrieves and closes the user's mediasoup producer in the old channel
      2. Emits PRODUCER_CLOSED to old-channel peers so they remove the
         dead audio consumer
      3. Calls mediasoup.cleanupUserSession() for old channel
      4. Calls presence.leaveChannel() for old channel (Redis)
      5. Leaves old Socket.io room
      6. Broadcasts PRESENCE_UPDATE with updated occupants for old channel

  Client Fix (renderer.ts):
    - Added isJoiningChannel boolean lock to handleChannelClick()
    - Prevents concurrent join attempts from rapid double-clicking
    - Lock is released in a finally{} block (success or failure)

  Client Fix (preload.ts):
    - joinVoiceChannel() now calls voiceService.cleanup() and recreates
      VoiceService with fresh signaling BEFORE starting the new handshake
    - Prevents stale transports from the old channel surviving into the
      new join attempt

  Protocol Changes: None (uses existing PRODUCER_CLOSED, PRESENCE_UPDATE)

  Key Files Modified:
    apps/server/src/handlers/connection.handler.ts
    apps/client/src/renderer/renderer.ts
    apps/client/src/preload.ts

--- Entry: 17/03/2026 ---

Feature/Fix: PRD 2.3 — Push-To-Talk (PTT) Mode Toggle

  Problem: The PTT shortcut acted as a simple mute toggle — pressing
  toggled mute, releasing toggled back. There was no overarching "PTT
  Mode" concept. The mic always started unmuted on voice join, and the
  PTT key worked regardless of mode setting, causing confusing behavior.

  Solution: Introduced a "Voice Input Mode" toggle with two modes:
    - Voice Activation (default): Mic starts unmuted on join. PTT
      shortcut is ignored. Standard mute button works as before.
    - Push-To-Talk: Mic starts MUTED on join. Holding the PTT key
      unmutes; releasing re-mutes. Standard mute button still works.

  Client Changes:
    1. voice.service.ts — Added setMuted(muted: boolean) for
       deterministic mute state control (avoids toggle drift from
       rapid press/release events)
    2. preload.ts — Exposed setMuted() on the reson8Api bridge
    3. renderer.ts — Added pttModeEnabled state (persisted to
       localStorage), auto-mute on voice join when PTT mode active,
       rewired all PTT keydown/keyup and global ptt-pressed/released
       events to use setMuted() with mode guard, added toggle button
       click handlers with mode-switch-while-in-voice support
    4. index.html — Added Voice Input Mode toggle buttons
       (🎤 Voice Activation / 🔘 Push-To-Talk) to Voice & Shortcuts
       settings panel, between audio device selects and shortcuts

  Server Changes: None (PTT mode is purely client-side)

Bug Fix: Channel Tree Occupant Visibility on Initial Connect

  Problem: When a new client joined a server, the channel tree showed
  all channels but with empty occupant lists. Users already in voice
  channels were invisible until they switched channels or the new
  client joined the same channel and received a PRESENCE_UPDATE.

  Root Cause: USER_JOIN_SERVER built the channel tree via
  buildChannelTree() which initializes occupants: []. The tree was
  emitted immediately without hydrating occupants from Redis presence.

  Fix (connection.handler.ts):
    - Added hydrateOccupants() function that recursively walks the
      tree and populates each channel node's occupants array from
      presence.getChannelOccupants() + presence.getUserPresence()
    - Called before emitting CHANNEL_TREE_UPDATE to the new client

    apps/server/src/handlers/connection.handler.ts

     BannedUser table and rejects with "You are banned from this server".

  3. Unban — Banned users appear permanently in a "Banned Users" section
     at the bottom of the Users modal (admin only, red styling with
     strikethrough text). Clicking "Unban" removes the BannedUser record
     and the user can reconnect.

Feature/Fix: PRD 3.2 — Voice Call Disconnect & "Unknown" Nickname on Reconnect

  Bug 1: "Unknown" Nickname After Reconnect

    Problem: After a network interruption and automatic reconnection,
    users' nicknames could display as "Unknown" in the channel tree.
    When a user disconnects, presence.leaveServer() deletes their Redis
    presence hash. If another client reconnects and triggers
    hydrateOccupants() during the brief window before the reconnecting
    user's new presence entry is written, getUserPresence() returns null
    and the fallback "Unknown" is used. This affected 5 locations in
    connection.handler.ts.

    Fix: Created a resolveNickname() helper function that tries Redis
    presence first (fast path, available 99% of the time), then falls
    back to querying the Prisma User table (slow path, covers the
    race-condition window). Replaced all 5 instances of the
    p?.nickname ?? "Unknown" pattern with calls to resolveNickname().

  Bug 2: Duplicate USER_JOIN_SERVER on Auto-Reconnect

    Problem: After a network interruption, Socket.io's built-in
    auto-reconnect (reconnection: true) fires the "connect" event
    multiple times, causing USER_JOIN_SERVER to be emitted repeatedly
    (up to 3 times within seconds).

    Fix: Added a joinServerInFlight boolean guard at module level in
    preload.ts. The socket.on("connect") handler now returns early if
    the flag is already set. The flag is set to true before emitting
    USER_JOIN_SERVER and reset to false in the acknowledgment callback
    and in the disconnect() method.

  Bug 3 (Stale Presence TTL): Already implemented — presence.service.ts
  has USER_TTL = 60 * 60 with TTL refresh on joinServer/joinChannel
  and a heartbeat() method. No changes needed.

  Key Files Modified:
    apps/server/src/handlers/connection.handler.ts — resolveNickname()
      helper + 5 fallback replacements
    apps/client/src/preload.ts — joinServerInFlight guard (3 locations)

  --- Post-Implementation Bug Fixes (23/03/2026) ---

  Bug 1: Noise gate permanently silences mic after silence
    Root Cause: producer.pause() (mediasoup-client) internally sets
      track.enabled = false. The AnalyserNode read from the same track,
      creating a feedback loop: once disabled it only saw silence, so
      dB = -Infinity, and the producer was never resumed.
    Fix: AnalyserNode now reads from a cloned track
      (originalTrack.clone()) which stays always-enabled, detecting raw
      mic input independently of the original track's enabled state.
    Files: voice.service.ts — added _analysisTrack field, clone logic
      in hookAnalyser(), cleanup in disableSensitivity() and cleanup()

  Bug 2: Adjusting sensitivity slider kills audio capture
    Root Cause: Slider's input handler called enableSensitivity() which
      invokes hookAnalyser(), tearing down and recreating the entire
      AudioContext + cloned track on every slider tick.
    Fix: Added setMicThreshold() method that only updates the threshold
      number without re-hooking the analyser. Exposed via preload bridge
      as setMicThreshold(). Slider now calls this instead.
    Files: voice.service.ts (setThreshold), preload.ts (setMicThreshold),
      renderer.ts (slider handler updated)

  Bug 3: Noise gate meter inactive outside voice channel
    Root Cause: hookAnalyser() requires localStream, which only exists
      after joining a voice channel via startProducing().
    Fix: Added startPreview()/stopPreview() preview mode to VoiceService.
      Creates a temporary mic stream + AudioContext + AnalyserNode for
      meter visualization only. Automatically stopped when joining a
      voice channel (hookAnalyser calls stopPreview). Exposed via
      preload as startMicPreview()/stopMicPreview(). Renderer starts
      preview when enabling noise gate outside a voice channel.
    Files: voice.service.ts (startPreview/stopPreview, _previewStream),
      preload.ts (startMicPreview/stopMicPreview), renderer.ts (toggle
      handler starts preview when not in voice)
