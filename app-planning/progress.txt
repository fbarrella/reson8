PROJECT OVERVIEW
================
Reson8 is a high-performance, self-hosted voice and text communication platform
for desktop (Electron). It replicates the TeamSpeak 3 experience — low-latency
voice, hierarchical channel trees, and private server ownership — while
integrating modern persistent text channels.

Tech Stack: Electron + TypeScript, Fastify + Socket.io, mediasoup (SFU),
PostgreSQL + Prisma, Redis, Docker.

Monorepo structure:
  apps/client/            — Electron desktop client
  apps/server/             — Node.js signaling + SFU server
  packages/shared-types/    — Shared DTOs, enums, and Socket.io event types

For build commands, environment variables, ports, and architecture details,
see the root CLAUDE.md (and apps/client/CLAUDE.md, apps/server/CLAUDE.md) —
not duplicated here to avoid drift between docs.

Full unabridged entry-by-entry history (every bug's root cause, every file
touched, every verification step) for everything summarized below lives in
app-planning/archive/progress-phases-1-8.txt (phases 1-8) and
app-planning/archive/progress-phases-9-10.txt (phases 9-10). The original
PRDs that drove this work are in app-planning/archive/ (PRD.md,
Reson8_Evolutions_PRD.md, Reson8_Improvements_PRD.md,
Reson8_NextSteps_PRD.md, Reson8_Phase10_PRD.md). Reach for the archive
when you need the "why" behind a specific decision that this summary
compresses away.

  PHASES 1-8 SUMMARY — ALL COMPLETE ✅  (current version: 1.1.0)

PHASE 1 — Signaling & Presence (Foundation)
  Fastify + Socket.io server (port 9800), Redis-backed presence tracking,
  Electron shell, typed Socket.io event maps, initial Prisma schema
  (Server/Channel/User/Role/Message), flat→nested channel-tree builder.

PHASE 2 — The Voice Bridge (mediasoup)
  mediasoup SFU integrated; full 6-step WebRTC handshake (GET_ROUTER_
  CAPABILITIES → CREATE_WEBRTC_TRANSPORT → CONNECT_TRANSPORT → PRODUCE →
  CONSUME → RESUME_CONSUMER); two-way audio; mute/deafen controls.
  Notable fixes: Electron mic-permission auto-grant, silent-audio race
  (queued consumption until recv transport ready), ICE announced-IP
  defaulting, detached-Audio()-element silence (must attach to DOM),
  deafen-toggle state flag, voice-control UI overflow.

PHASE 3 — Relational Logic & Hierarchy
  DB seeding (default server/channels/roles), channel CRUD over Socket.io,
  three-pane TeamSpeak-style UI (tree + log + status bar), click-to-join
  voice with occupant display, create/delete channel modals, production
  Docker Compose (server + Postgres + Redis).
  Notable fixes: window.confirm() unusable in Electron renderer (replaced
  with custom modal), modal input pointer-events/drag-region fix.

PHASE 4 — Permissions & Persistent Text
  Instance-based identity: persistent UUID per Electron install (fresh
  each launch in dev, persisted when packaged), auto-creates User +
  default role, ADMIN_INSTANCE_ID env var grants admin. Bitwise
  permission service + requirePermission() middleware. Permission-guarded
  channel CRUD. SEND_MESSAGE/FETCH_MESSAGES with cursor pagination.
  Tabbed chat UI. 11 unit tests added (permissions.test.ts).

PHASE 5 — Desktop UX, Audio Polish & Admin
  Unified Settings modal (Roles / Voice & Shortcuts tabs). Role management
  UI (toggle Member/Admin, admins can't self-demote). Audio device
  selection (input/output, localStorage-persisted). Multi-key shortcut
  combos for PTT/Mute/Deafen/Disconnect via Electron globalShortcut.
  URL-based server connection. Instance ID visible in footer.

PHASE 6 — Deployment & Packaging
  Server Dockerfile + entrypoint.sh (migrate → seed → start). Electron
  Builder config: Windows NSIS, Linux AppImage+deb, macOS dmg. Electron
  pinned to 34.5.8. Packaged-build instance ID persistence via
  app.isPackaged.

PHASE 7 — Evolutions (PRD 2.x — 14 items + moderation system)
  - Fixed dual-voice-channel race condition (full mediasoup + presence
    cleanup of the old channel before joining the new one; client-side
    join lock)
  - Public/private dual-announce IP (MEDIASOUP_PRIVATE_ANNOUNCED_IP) for
    hairpin-NAT self-hosters
  - Push-to-Talk Mode toggle, decoupled from the manual mute button
  - Explicit "Save" action for audio device changes (staged pending state)
  - Fixed channel-tree occupant hydration on initial connect
  - "Remember Me" — persists server URL/nickname/password in localStorage
  - Server password protection (SERVER_PRIVATE_PASSWORD env var)
  - Direct Messaging: full 1-to-1 DMs with persistence, Online Users
    modal, read receipts, unread indicators, auto-opening unread tabs
  - Rich media: image upload/paste sharing, dual storage (local disk or
    Cloudinary CDN), lightbox viewer
  - Active Speaker Indicator via server-side mediasoup AudioLevelObserver
    (pulsing halo on the channel-tree presence dot)
  - System Tray: minimize-to-tray, close-to-tray, tray context menu
  - Rich link previews (metascraper via main-process IPC, sanitized HTML,
    video embed support with fullscreen lightbox)
  - Emoji Selector: ~350 curated emojis, categorized + searchable
  - Native right-click context menu (Cut/Copy/Paste/Select All via
    Electron's Menu API)
  - Persistent DM conversations — history remains accessible once a
    partner goes offline (first-contact still requires both online)
  - Kick from Channel & Ban from Server moderation system (instance-ID-
    keyed bans with unban support)

PHASE 8 — Improvements (PRD 3.x — 5 items + 3 extras)
  - Fixed tray icon invisible in packaged builds (assets/**/* added to
    electron-builder's build.files)
  - Fixed "Unknown" nickname / duplicate-join-on-reconnect (resolveNickname()
    DB fallback for Redis-presence races; joinServerInFlight guard)
  - Sound Alerts System: 16 event-mapped audio cues (connection, voice
    presence, moderation, mute/deafen, DM notification gated by focus)
  - Mic Sensitivity Slider (noise gate): AnalyserNode-based silence
    detection with configurable dB threshold + live meter; 3 post-impl
    fixes (cloned-track analysis to avoid a mute feedback loop, threshold-
    only update to avoid re-hooking the analyser on every slider tick,
    preview mode for the meter outside of voice channels)
  - Voice Channel Session Timer: server-authoritative session start time,
    displayed in the channel tree and voice panel, synced on reconnect
  - Extra: Settings button always accessible even when disconnected
  - Extra: Emoji Reactions on messages (persistent, toggleable, tallied)
  - Extra: Real-time latency display (color-coded ping in the status bar)

PHASE 9 — Next Steps (PRD 4.x — 15 items, reached v1.2.0)
  - Per-user local voice volume (0–200%) and per-user local mute via a
    GainNode-per-participant Web Audio graph (client-local only, never
    sent to the server); localStorage-persisted per userId (PRD 4.1/4.2)
  - Self mute/deafen status icons: extended Redis presence + a new
    SET_VOICE_STATE event so isMuted/isDeafened (previously hardcoded
    false in 6 places server-side) reflect real client state (PRD 4.3)
  - Channel rename (reused an already-built but unwired UPDATE_CHANNEL
    event), NSFW text-channel flag + confirmation modal, and sibling
    drag-and-drop reordering via a new REORDER_CHANNELS event (atomic,
    MANAGE_CHANNELS-gated, admin-only drag affordance) (PRD 4.5/4.6/4.7)
  - Custom emoji uploads with an admin approval queue: new CustomEmoji
    model + MANAGE_EMOJIS permission, cover/pan/zoom crop tool, "+"
    picker tab, :name: token rendering shared with reactions (PRD 4.8)
  - 178 new default emoji (374 → 552 unique), plus a pre-existing
    duplicate (🔥) caught and fixed during the audit (PRD 4.9)
  - Delete own messages/DMs (hard delete) and edit own channel messages
    within a 2-minute server-enforced window; introduced
    storage.service.ts's deleteAttachment() (Cloudinary vs local-disk)
    shared by both delete paths and later reused by emoji rejection
    (PRD 4.10/4.11)
  - Instant upload feedback: local thumbnail + spinner appear the
    moment a file is picked/pasted, with an inline retry on failure
    (PRD 4.12)
  - Unread text-channel indicator via a new ChannelRead cursor table;
    tracked live client-side (MESSAGE_RECEIVED already broadcasts
    server-wide) with the cursor only needed to restore state on
    reconnect (PRD 4.13)
  - Shortcut-triggered mute/deafen/disconnect now play the same sound
    cues as their button equivalents (PRD 4.15)
  - Nudge: first true "server-wide setting" (Server.nudgeEnabled,
    admin-toggleable), 30s per-(sender,target) in-memory cooldown,
    sound + toast + taskbar/dock flash (PRD 4.14) — final item, all 15
    complete

  Post-Phase-9 fixes (found during manual verification, before Phase
  10 began):
  - Unread indicator reappearing after any voice join/leave (stale
    cached hasUnread on the tree node was never cleared by
    markChannelRead(), only the separate unreadChannelIds Set was)
  - Custom emoji upload silently doing nothing (CSP blocked `blob:` in
    img-src, so the crop tool's image preview never loaded/advanced)
  - Settings modal admin-tab flicker for non-admins (tab visibility now
    decided from a cached connect-time permission check, before the
    modal's first paint, instead of after an async re-check)

PHASE 10 — Auto-Updater, Audio Settings & Mute/Deafen Fixes (PRD 10.x —
6 items, reached v1.3.0)
  - Client auto-updater via electron-updater: check/download
    separation, 1-attempt-plus-3-retries-20s-apart shared by an
    automatic packaged-only startup check and a manual "Check for
    Updates" button, new "About" settings tab, GitHub Releases publish
    config (PRD 10.1)
  - Audio settings tab: Nudge / Sound Alerts / Global Voice Chat volume
    sliders (0–100%), the last multiplying into the existing per-user
    gain as a master attenuator (PRD 10.2)
  - Fixed the voice session timer blinking blank on every mute/deafen
    toggle (timer text now computed synchronously at render time
    instead of waiting for the next 1s interval tick) (PRD 10.3)
  - Mute/deafen accumulation: deafening now always auto-mutes the mic
    (remembering whether it had to), undeafening restores exactly the
    prior mute state, PTT is fully blocked while deafened, and clicking
    Mute while deafened auto-undeafens then applies a normal toggle —
    a user decision overriding the PRD's original "no-op" default
    (PRD 10.4)
  - Fixed a false-positive unread indicator on a user's own last
    message (excluded the sender's own messages from the unread query,
    and SEND_MESSAGE now advances the sender's own read cursor)
    (PRD 10.5)
  - Fixed the AppImage showing a generic icon instead of Reson8's on
    Wayland (explicit BrowserWindow icon, app.setName(), and a
    matching StartupWMClass) (PRD 10.6)
